# Status-check names bin/enable_repo_rules.sh makes merge-blocking on the default branch.
# One name per line, verbatim as GitHub reports it; blank lines and `#` comments ignored.
#
# Add a name only after confirming a real PR emits it:
#   gh api repos/:owner/:repo/commits/<pr-head-sha>/check-runs --jq '.check_runs[].name' | sort -u
#
# A name nothing emits blocks every PR forever — GitHub cannot tell "has not reported yet"
# from "will never report". Deleting a line is always safe; adding an unverified one is not.

# ci.yml — `on: pull_request` with no filter; both jobs carry a literal `name:` and neither has
# a job-level `if:`, so both report on every PR from the moment it opens.
Lint — shellcheck + shfmt
Test — bats
