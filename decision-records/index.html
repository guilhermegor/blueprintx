    Generated-project test suite (templates/python-common/tests)¶

    The tests every Python scaffold ships carry no comments. The shapes below recur across the suite; each exists because a simpler form was measured to be wrong or to hide a failure. The module layout the old banners spelled out is plain order now: helpers, fixtures, then tests.

    Shapes forced by the complexity ceiling¶

    tests/ is held to cyclomatic complexity 1 by bin/check_complexity.sh, so a test body has no branch. That is the mechanical form of "a test exercises one path"; a branch in a test means the green never says which side ran.

    • Comprehensions, generators and contextlib.suppress replace loops with skip guards, try handlers and flag variables: mccabe charges a comprehension nothing and charges every loop, guard and handler a point (test_startup_fragility_order, test_contract_family_conventions, test_integration/test_bin_scripts, test_wheelhouse_select). A short run of three calls or entries is written out rather than looped for the same reason.
    • skipif decorators over a body guard. An environment probe is resolved once at import time and feeds a skipif, because if ...: pytest.skip(...) in the body reads as a path through the test to a reader and to mccabe alike. The same applies to "does this tier ship the package or driver" (test_all_exports_gate, test_daily_cache, test_ruff_ret_rule, lint_deps).
    • Module-level helpers and stubs, never nested defs. A nested function costs the enclosing test one point, so a branch-free stub would spend the budget reserved for branching (test_pr_gate, test_sidecar_metadata, test_retry).
    • Mock(side_effect=[...]) for a flaky callable (test_retry, test_review_retry): the call sequence "raise, raise, return" is data where a reader looks for it, not an if on a counter, and functools.wraps tolerates a Mock. A conditional expression keeps the opt-out fixture in conftest.py at complexity 1: a test that opted out is patched back to the real primitives, a no-op that monkeypatch undoes at teardown anyway.
    • parametrize, not a for in the body. A loop asserts N cases behind one green: the report cannot say which case ran and the first failure hides the rest. A reference date, one token map and three documented tokens is one assertion over different keys (test_paths). Where a case list must be flattened, flatten first and assert once on the collected names so every offender is reported (test_startup_fragility_order).
    • An immutable default for env-override parameters. A mutable {} default is a bugbear B006 finding and a dict_extra or {} guard costs a decision point; short-circuit evaluation makes a helper an expression instead of a branch (test_bin_scripts).
    • One build, several facets. The "expensive shared setup" pattern in tests/CLAUDE.md, module-scoped, stops the one-assert rule from turning three claims about one read-only frame into three rebuilds of it (test_frames, #544). pytest.raises plus its match= is one assertion site with one failure mode, not two (test_pip_requirements).
    • Split rather than combine. A conjunction in one assertion reports only that the whole was false: an absent loader and an absent spec are different faults (test_all_exports_gate, test_layer_imports_gate, test_review_retry). An introspective test over __all__ beats five hand-listed imports, so a name added to a package without being exported is what fails (test_retry, the surface added in #116).

    Witnesses and negative controls¶

    • Every gate needs a test that has seen it fail (#111). A gate with no should-fail witness is indistinguishable from one that is not wired up, since both print green. Writing the first eight found three live defects: check_provenance.py and check_docstrings.py both exited 0 printing nothing when their cwd-relative globs matched nothing, and lint_actions.sh accepted any file named actionlint on PATH as a working one. The lint_*.sh wrappers need a witness for both the missing-tool branch and the zero-discovery branch, since "tool not found" and "tool ran and passed" look identical from outside.
    • A healthy tool is required for the zero-discovery witness. With actionlint absent the run stops in the required-tool branch and never reaches discovery, so an assertion that also accepts "required" stays green with the guard deleted. Poetry is shadowed there so resolution cannot take the vendored path.
    • A fixture must reach the boundary it claims to test. A 100-digit input sat under Python's 4300-digit conversion limit, exercised only the OverflowError path and passed while the ValueError path was open; it is 5000 digits (test_review_retry). A multi-line docstring that closes on a line starting with text is required for #206's third shape: a one-line docstring matched the old start-anchored guard and proved nothing. Fixture halves that a gate keys on disagreement over must genuinely differ (annotated -> int, documented as str).
    • A scanned-nothing control keeps a gate from becoming decorative. A gate that scanned nothing also found nothing wrong and would report OK forever after a rename; the zero-discovery and could-not-parse cases pin that for each gate (test_all_exports_gate and siblings).
    • Real wording, verbatim. The reviewer's refusal text and declared wait come from the live message (#275, 2026-08-26): the phrase is the interface, and a paraphrase would test our idea of the message while the parser only ever meets the real one (test_review_retry).
    • Relative paths where the gate takes relative paths. swallowed_by_omit is called with a relative path_module after a chdir to the project root. Passing an absolute path makes each test vacuous: it matches the absolute branch and the relative pattern is compared with a path that can never match. With the absolute branch reverted out of the gate, the earlier versions still reported 2 passed (test_coverage_floor_gate). Gates that derive PATH_ROOT from __file__ (check_docs_code_refs.py, check_function_length.py) are pointed at a throwaway tree with --root, because cwd= alone would scan the real repo.

    The dual import root¶

    pytest.ini puts both . and src on the path, so one file is importable as utils.x and as src.utils.x, and Python loads it twice with distinct class objects. A module that annotates a parameter with a class it imports bare (ProblemReport, FileContract, RegimeWindow, LogEmitter) is guarded by beartype or the runtime TypeChecker, whose nominal check rejects an instance built from the other copy. So these tests import bare (utils., config.), never src.utils.; tests/CLAUDE.md ("The dual-import-root trap") has the rule. The names are interchangeable until a class crosses between them. Affected modules: test_daily_cache, test_provenance, test_regime_adapters, test_ms_office_excel_sheet_names, test_xml_reader, test_sidecar_metadata, test_config_schemas_example, test_contract_oracle_example.

    • test_bin_scripts (integration).
      • Subprocess argv is a constant, trusted list built from repo-internal paths with no shell, so bandit's subprocess warning is a false positive; each call carries its own noqa.
      • The environment is inherited, not scrubbed: an emptied PATH takes dirname with it, so SCRIPT_DIR never resolves and the run fails for a reason unrelated to the claim (measured). poe_exec.sh is run under either branch of the resolver, since a resolved Poe and the "none found" diagnostic are both built from print_status, so either proves the lib is reachable.
      • poetry_exec.sh: stdout is exactly the project version, and the resolution status lands on stderr. precommit.sh: the skip-gracefully default exits 0 and announces the skip without fabricating a repository or running git init; with a real work tree a throwaway HOME isolates the global safe.directory write, and the self-heal never emits the "no git repo" skip.
      • pip_fallback.sh driver pruning: config/connection_db.py lowercases DB_BACKEND before dispatching, so those spellings are valid configuration and the pruner must agree, or it drops the one driver the project uses.
      • bin/check_*.py on Windows: cp1252 stdout must not crash the glyph that check_dtypes prints for a banned binary float dtype.
      • bootstrap.sh: a corporate CA must be unioned with the existing roots, never replace them. A replacement writes exactly one block, while only a union carries the roots too. certifi's absence is simulated by hiding it from the child with a finder written against the modern protocol: the older two-method form was dropped in Python 3.12 and a finder shaped that way is skipped without a warning. The supported path reads the store the browser trusts.
      • get_corporate_ca.sh: the refusal carries the remedy, not only the verdict, and nothing is written on the refusal path. check-clean-index: editing a tracked file without staging it leaves the tree dirty and the index empty, the routine state the guard must never block; git add with no commit consuming it is the fingerprint of a rejected commit, and the verdict names the likely cause, the file and the remedy including the escape hatch.
      • export_deps.sh: Poetry's own words survive to the operator, and the remedy names the resolved binary, not a bare poetry. print_status: an unknown status must not look like ordinary output.
      • check-urls (#206, #224): every docstring shape must actually be scanned. The three shapes each hold the same unreachable URL, so a shape that reports clean is a check nobody ran. The third (a closing delimiter sharing a line with text) was never blind, since the URL was scanned as body text, but the state never flipped back, so every later line was read as still in the docstring. The cache key mirrors the hook's own md5sum, not a security use.
      • check_complexity.sh (#167, #254): a function with complexity 3 (two ifs plus the implicit path) is over src/'s ceiling of 2 and under bin/'s 8. The colour-control variables are stripped from every run so a developer's shell cannot decide what the suite measures; the ANSI CSI pattern is matched so escapes never reach the gate's parsing; the reported finding is a regex over the whole line, and print_status adds colour, so only the ruff-derived remainder after C901 is asserted clean.
      • rerun_stale_gate_runs.sh: a scriptable gh shadows the real one and records every call. Shadowing, not mocking, because it is deterministic on any machine including CI, where the real gh is installed and a skipif would drop the coverage where it matters. It does not evaluate --jq: filtering is GitHub's job, so the tests assert on the query sent.
      • lint_deps.sh (#238): the manifest declares nothing, so any third-party import under src/ is undeclared by construction. PEP 621 is used rather than [tool.poetry], which does not drift when the tier's Poetry moves. The test imports a package every tier declares, installed in the venv yet absent from the throwaway manifest: present at run time today and gone the day whatever pulled it in stops doing so. The wrapper's shift 2 drops run and deptry, leaving its own arguments.
      • run.sh (#252): an argument passed to poe run <x> must reach the entrypoint; the test file is made newer than pyproject.toml with a margin so the -nt check in runtime_env_needs_bootstrap is unambiguous at any filesystem mtime resolution.
      • test_resourcewarning_unraisable_gate: constant trusted argv from sys.executable and repo-internal paths, so the bandit warning is a false positive.
    • test_backlog_ledger and the integrity gates. classify_risk returns the single most dangerous class and ranks tests above ci, so a branch touching bin/ and tests/ collapses to tests, not a ledger class. One test pins that collapse, the other that asking per path still catches it; they are two tests because they assert different functions. The bot exemption (#123) is tested in both directions by name, because an exemption is one return 0 from disabling the gate for everyone with the suite green. robotics-team and dependabot are the load-bearing cases: "bot" inside a name is not the suffix, and only GitHub's own marker counts. A gate demanding a human-authored artifact otherwise blocks every bot PR. Gate integrity (#309) is pure logic, offline; assertion integrity (#324) covers a test's expected value edited to match a bug, with the line number as a case, since a finding that cannot point at its assertion sends the author hunting. A renamed test file is read at its source path (#590), with padding to keep git's rename similarity above 50% after the one-line weakening; an expected-value change counts only when production code also changed (#289 is the live example). The #334 review added three ways the guard could be defeated or misfire.
    • test_pr_gate. Terminality differs from display state: {"a": "failure", "b": "pending"} displays as failure while not terminal, and breaking the poll loop on gate_state() != "pending" would stop on the first transient red while other checks run, with nothing re-rendering the comment afterwards.
    • test_regime_adapters. resolve returns the first covering window while the registry promises windows may arrive in any order, so two overlapping windows bind a period to whichever was listed first, a reader parsing a real file against the wrong published header with nothing reporting it (#344 review). Validation the caller can undo is not validation, hence the regression for it.
    • test_paths. The premise (PureWindowsPath("/home/x/out") is rooted but driveless, so is_absolute() is False) and the behaviour (the function routes through resolve()) are separate claims and must not collapse (#544): asserting only the premise pins the platform and leaves our function untested, since a regression handing the driveless input back would pass. On POSIX CI the verdict is simulated and the real function is then called under it.
    • test_daily_cache. write_bytes is not atomic, so an interrupted run can leave an empty file; serving it hands the caller a valid-looking path to nothing that fails later and far away. The miss, the hit on the same reference day, and the half-written file each get a case.
    • test_frames. An empty frame with no columns makes the shape data-dependent: a caller that concatenates or renders it behaves differently depending on whether rows existed. Returning the declared columns keeps it constant; both seams owe the property, empty and still shaped. apply_dtypes needs disjoint column sets, so a date column is declared by list_date_cols alone, never also in dict_dtypes.
    • test_startup_fragility_order. The reference block is an optional override and must never force a project to declare a source's {dir, pattern} twice; the tests pin the fallback chain (override wins, the real input's own spec otherwise, None only when neither exists), with the absent-override path asserted explicitly since every existing project has no reference_files and that path is where a regression lands first. The try-block check is scoped to the one that wraps the config read, since the module has a legitimate except ModuleNotFoundError for the typing shim. These tests live in this module because a new tests/unit/*.py needs its own scaffold copy-list wiring (bin/ci/check_test_copy_lists.py).
    • test_contract_family_conventions. The list of column names two contracts legitimately share stays empty by default and a conscious list: two sources requiring cnpj is ordinary, so the check's value is that sharing is declared, not forbidden.
    • test_comment_language_gate. Two consecutive comment lines form a quotation that opens on the first and closes on the second; read line by line, the opening quote never meets its closing one, the quoted span survives redaction and its language is charged to the English comment. Each false positive was measured and is pinned by name, accented capitals included (NÃO). The environment is inherited because a bare dict drops PATH; discovery reads git ls-files (#331), so an untracked fixture tree is invisible and the fixture must be a committed repo, with an orphan worktree stand-in present on disk but never staged. One representative long-lived file per location the allow-list once missed is checked. Registering the module root makes teardown undo the rebind the gate performs.
    • test_comment_budget_gate. The ratchet ceiling, the escape hatch, pragma lines breaking a run, the decorative banner (regex-decidable, no ratchet), positional exemptions, the extensionless Makefile as the issue's own worked example, and that Python files are checked (#466).
    • test_logs. A StreamHandler flushes on every record, so the old flush loop was dead code; the caller prefix is rebuilt by walking the stack, so the pattern asserts the shape and ends at the message, which also proves it was written; closing a FileHandler sets its stream to None, a deterministic signal independent of garbage collection.
    • test_raw_workspace. The criterion is what is not on disk afterwards, so the assertion runs outside the block. A caller naming a leaf inside an unbuilt tree must not assume the parent exists, or a bronze write dies on the first run of a new dated folder. The runtime checker guards against the string form, which would otherwise fail at str.mkdir later.
    • test_tabular_reader. A stray quote opens a free-text middle column; under default quoting the open quote swallows the separator and the trailing rows, while QUOTE_NONE keeps the three real fields.
    • test_typing. Under the default policy a bool is rejected where an int is annotated; flipping the strict-bool knob off on the seam and rebuilding the config makes the bool satisfy it, proving the knob and not the adapter drove the change.

    Generated-project config files (templates/python-common)¶

    The config files every Python scaffold ships carry no comments. This section records why each is shaped as it is; a generated project gets the behavior, not the history.

    Small config files¶

    • .codespellrc.
      • skip is the single source both gates read: poe lint scans the whole tree and pre-commit only staged files, so they agree only because the skip lives here. *-lessons.md is a git-ignored mirror that the lessons workflow writes, not a build output; without the skip, writing a lesson would flag the mirror and abort an unrelated commit. Use the basename glob, never docs/*-lessons.md: codespell . walks ./docs/... and an anchored pattern silently fails to match.
      • ignore-words-list is the locale extension point. codespell only knows English, so a technical doc in another language (the seed is pt-BR) is flagged at the pre-commit boundary, and each rejected commit costs a full gate run. Extend the list with your locale's vocabulary; never skip a whole file, which hides real typos in identifiers. The second half of the list is commit and doc prose (ser, vai, meu, ...), not domain nouns. Write every entry lowercase: codespell lowercases the found word before the lookup, so a capitalised entry matches only itself. Keep it in sync with the repo-root .codespellrc; the two drifted in both directions and the stale copy was this one. Entries are pruned by measurement (#197): drop one, re-run, keep it only if a finding appears.
    • .coveragerc. Branch coverage and the floor are measured as described in Coverage floor (#427). bin/check_coverage_floor.py guards the patterns: one must never widen past infrastructure/ (or a whole capability named outright) into a domain/ or application/ layer, which would drop real logic from the fail_under denominator (#149). fail_under is the single literal read by pytest-cov in both the pre-commit hook and the CI gate.
    • .cz.toml. Commitizen config lives here, not in pyproject.toml, so the manifest stays near package identity and dependencies (#233); the keys were identical across the five Python tiers, so it is one file copied to each. Commitizen tries pyproject.toml first and skips it when it has no [tool.commitizen], so this file is found; but if it ever stops being copied, commitizen does not fail: cz version --project prints "No project information" and exits 0, giving a differently formatted changelog and an unprefixed tag, never a red check. That is why scaffold_lint_test.sh asserts the file lands. Consumers: poe bump_version, poe changelog, the commitizen and commit-msg hooks, and the docs build. version_provider = "poetry" reads [tool.poetry] by project root, not by where the config lives. Services keep the version in pyproject.toml, tagged by cz bump (offline) or release.yaml (online); the library tier takes it from the git tag via poetry-dynamic-versioning. Either way cz changelog groups by tag.
    • docker-compose.otel-collector.yml. Ports are bound to 127.0.0.1, not published on every interface. The OTLP receivers are unauthenticated and the file is copied into every project that opts in, so a bare 4318:4318 would make an open log sink the default on whatever network the box sits on. A deployed collector belongs behind a real ingress with credentials. 4318 is OTLP/HTTP, which OTEL_EXPORTER_OTLP_ENDPOINT points at; 4317 (gRPC) is unused by the HTTP exporter and kept for a gRPC one.
    • otel-collector-config.yaml (#438). The collector is the decoupling point: repoint the logging exporter at Axiom, Loki, Datadog, SigNoz, Honeycomb, Elastic or any OTLP backend, a config change and never an application change. 0.0.0.0 is correct and must not be hardened to 127.0.0.1: it is the bind address inside the container, whose loopback is not the host's, and narrowing it makes the collector unreachable through the port mapping while the fire-and-forget exporter reports nothing. Host exposure is controlled in the compose file. The logging exporter prints to the collector's stdout, enough to prove the seam end to end.
    • docs/.docs-skeleton.yaml. Overrides the required-page set check_docs_sections.py enforces. It adds architecture.md, which describes a service's layer structure and was scaffolded but never enforced (#130). It is copied into the four service tiers; lib-minimal has no architecture.md, never receives the file and keeps the default set.
    • .gitignore. dist/ is ignored but dist/.keep is tracked, so the directory ships. Only the curated VS Code settings and tasks are tracked. coverage.svg is tracked (the README badge references it); coverage.xml is regenerated on every run. The Claude Code .tmp.<pid>.<hash> mid-save sibling is ignored so a racing git add -A cannot sweep it into a commit. The scaffoldable-lessons working copies are local; the canonical stores are global. The SQLite file is the DB_BACKEND=sqlite default DB_PATH=./data/app.db and is never committed. The corporate CA and the union bundle derived from it are generated locally.
    • .gitleaks.toml. It extends the default ruleset rather than replacing it, and keeps the allowlist to what a fresh project measurably needs, not a speculative list copied from another app's surface (#305). Extend it as real false positives are measured, as .codespellrc grows. The stopwords are the placeholder markers in .env.example and the README, never real secrets; a value containing one is ignored. The lockfile is allowlisted for pinned package-hash entropy.
    • .gitlint. The limits were implicit (gitlint's defaults) and were found only when a commit was rejected after the slow hook chain had run. Commitizen enforces the Conventional-Commits format; gitlint owns the length limits.
    • .hadolint.yaml. A project may ship no Dockerfile, in which case the hadolint-docker hook skips. The baseline lets one that adds a Dockerfile inherit a starting point. hadolint lints Dockerfiles only; compose files are covered by check-yaml and yamllint. It fails on warnings and above (info and style are advisory). Seed trustedRegistries (DL3026) and ignored per project, for example DL3008 (pin apt-get versions) or DL3059.
    • .layer-policy.yaml (this directory's own copy, checking python-common/src). The directory is a staging area, not a project, which is why it went unchecked: the gate self-skipped without a policy, so the code shipped to every tier was the one tree the boundary was never applied to. A third-party dependency is reached through a seam in utils/, never imported by model/, view/ or controller/, so a vendor change stays in one adapter. Deferring an import into a function buys no exemption. Every allow entry carries a reason, since an unexplained allowlist entry is one the first inconvenienced person widens. chassis is first-party but absent from this layout (the DDD name for the typing shim's home). pandas is allowed as a type annotation only: -> pd.DataFrame is shared vocabulary, pd.read_sql(...) is a vendor API call every copy inherits. utils/ is the seam layer and is listed explicitly so a new vendor needs a conscious decision. A stray module directly under src/ is named so it cannot bypass the policy. The composition root knows concrete implementations but not the domain.
    • .pydocstyle. Ruff already enforces the NumPy docstring set; pydocstyle adds the two checks ruff lacks, D412 and D417. The list matches the hook's --select, so poe lint (a bare pydocstyle .) and the hook enforce the same thing.
    • pytest.ini. PytestUnraisableExceptionWarning is escalated as well as ResourceWarning: a warning raised inside __del__ is unraisable, so pytest re-emits it as the other class and error::ResourceWarning alone never sees it, letting a leaked file handle pass (#294, the shape #223 shipped). The second line is the whole mechanism for __del__; do not delete it as noise. A warning is ignored by source, never by class alone: a bare ignore::DeprecationWarning hides every deprecation, including ones aimed at this code. With the four blanket lines removed the suite emitted four warnings, all from one vendor.
    • requirements.txt is the bootstrap install. poetry-plugin-export is pinned here and not only as a dev dependency: a dev dependency reaches the project venv and nothing else, so the recipe would work from an activated shell and fail from cron, CI and the offline host it serves. poetry-plugin-shell (Poetry 2.x dropped poetry shell) lives here for the same reason: a Poetry plugin must live in the interpreter Poetry runs from, and as a project dependency it would sit in .venv, where no Poetry exists to load it.
    • .review-bots.yaml. The roster is the provider-agnosticism: the gate names no tool, it subtracts these logins from a thread's authors. Reviewer shapes differ: some post inline threads, some post only a status check. posts: is required on every row and decides more than authorship (#218): a posts: status member is excluded from the missing-review gate too, so a workflow submitting a review with the ambient GITHUB_TOKEN cannot satisfy a gate that exists to say a real reviewer looked. A row that omits it or spells it otherwise fails loudly; at least one posts: threads member is required. Zero threads is judged against a submitted review, never against silence (#208). Delete the file to opt out: the gate self-skips with a message. See also the records at the top of this page.
    • .shellcheckrc. severity=warning is the level at which the scripts are clean while still catching real bugs (unquoted expansions, undefined variables, bad test syntax). SC1091 is disabled because lib/common.sh is resolved at run time, not lint time.
    • .sqlfluff. The top-level dialect is a fallback for a .sql file outside the per-engine layout. Mixing engines needs no change here or in bin/lint_sql.sh: queries live in src/config/queries/<engine>/<table>__<purpose>.sql and sqlfluff resolves config per directory, so each engine's folder carries a one-line .sqlfluff with its dialect. The engine is a directory, never a filename prefix, which would declare it twice and could disagree. Positional ? bind parameters are swapped for a stub by the placeholder templater, since a bare ? is not SQL. Indentation is a tab, matching the project convention (ruff, shfmt and Make use tabs; only YAML is forced to spaces). Hand-written SQL keeps a readable style with identifier casing dictated by the source schema, so those opinion groups are excluded while parse-correctness and keyword capitalisation stay on.
    • .yamllint complements check-yaml, which only validates that YAML parses, with style checks. It is relaxed where the config YAMLs are intentional: no line-length cap (long documentation comments and email bodies), no --- start marker, aligned values with extra spaces after the colon (outputs_*.yaml), and truthy values that appear inside quoted strings, not as bare booleans.

    mypy.ini¶

    • Run from src/ (cd src && mypy --config-file ../mypy.ini ., in the pre-commit hook, CI and poe). That makes src the single package base, so the bare imports (config.x, utils.x, model.x) resolve as at run time (pythonpath = . src in pytest.ini). From the repo root, with mypy_path = src and files = src, the root and src compete as bases and a file resolves twice ("found twice under different module names") on the deeper DDD tree.
    • No python_version pin. Pinning below the running interpreter makes mypy parse the installed third-party stubs under older syntax rules. On Python 3.12 Poetry resolves numpy 2.5 or newer, whose .pyi files use PEP 695 type statements, and python_version = 3.10 fails on numpy/__init__.pyi in every tier that imports pandas. Capping numpy would move the break to the next dependency that adopts PEP 695. The floor is enforced where it is sound: the CI 3.10 matrix leg runs mypy on 3.10, and ruff's target-version = py310 catches too-new syntax in our own code.
    • ignore_missing_imports = False (#376). A global True cannot tell "pandas ships no stubs" from "this first-party module does not exist in this layout", so a typo'd utils.x reported Success. Stub-less vendors get one [mypy-<vendor>.*] block each, derived by measurement (flip the line locally, scaffold, read the import-not-found errors), because a hand-written list that misses one turns a green gate red in every generated project. Current blocks and their import sites: pandas (the utils readers, dtypes, frames, provenance; MVC controller, model and view), wwdates (utils/dates.py), defusedxml (utils/xml_reader.py), win32com (utils/ms_office/outlook_gateway.py), yaml (config/startup.py), pyodbc (the native-DB MSSQL handler, the only one of the five native drivers with no stubs) and joblib (the schema-less opt-in's joblib_handler.py, #650, which a scaffold with no opt-ins never imports). openpyxl is named in docstrings but never imported, so it is absent: an unmeasured entry is the guess this scheme exists to stop.
    • Baseline strictness. Annotations and obvious type errors are enforced, not --strict, so the runtime-TypeChecker metaclass machinery does not drown the signal. Tighten later.
    • The one exclude is the runtime type-checking engine (utils/typing or chassis/typing, nested at <pkg>._internal.utils.typing in lib-minimal): intrinsic metaprogramming mypy cannot analyse, the same reason it is ANN401-exempt. It matches ruff.toml's exclude (#203). ^chassis/ and ^capabilities/example_feature/ were both removed in #190: chassis was unchecked and had accumulated 20 errors in the DB handlers while shipping into every DDD project; example_feature was excluded yet checked anyway, because main.py and app/container.py import it. Dropping it took the DDD native tier from 58 to 69 checked files with zero new errors. An exclude that excludes nothing advertises a protection that is not there.
    • Keep both mechanisms, exclude and the per-module ignore_errors sections. exclude filters discovery only and does not apply to a module reached through an import, so it holds only while nothing outside the tree imports it, a property of the wiring and not of the config. Adding config/query_loader.py (#119) took the DDD native tier from "no issues in 31 files" to "20 errors in 5 files", none in a file the change touched. Those 20 were fixed (#190), which is why no [mypy-chassis.*] section exists. Do not add one to quiet a new error.
    • The typing-engine sections carry ignore_missing_imports as well as ignore_errors (#376). Every shared src/utils/*.py helper reaches the engine through one try: from utils.typing import type_checker / except ModuleNotFoundError: from chassis.typing import type_checker; a separate TYPE_CHECKING branch was measured not to change which import mypy reports (#360). mypy always tries utils.typing first, and on a DDD layout it genuinely does not exist: a deliberate shim, the one first-party import still tolerated. Narrowing [mypy] alone turned every shared utils/*.py red on DDD; MVC reports 0 errors either way.

    • target-version is the floor of requires-python (>=3.10); bump it in lockstep with pyproject.toml.
    • exclude. src/chassis and src/capabilities/example_feature were excluded until #203, mirroring #190's mypy fix. They ship verbatim into every DDD project, so a defect or a style violation the rest of the tree is held to propagates. About 230 findings were fixed in place (D202, S608 noqa'd per line, UP007/UP035, missing ANN204/ANN202, a docstring hanging indent authored before the tree was tabified); a few per-file ANN401 ignores remain where Any is honest. lib-minimal vendors the typing engine at a nested private path whose imports are rewritten to <pkg>._internal.* and can exceed the line length, so it is excluded in full (mypy excludes it too).
    • Preview mode is for PLR1702 only (too-many-nested-blocks, still preview-only in ruff 0.11.13). It also activates 10 tag-along preview rules in the PL and S families, never chosen on their merits, so they are ignored explicitly (#434): --preview alone raised findings from 21 to 81 on templates/, and ignoring exactly those 10 restores 21. Revisit each on its own measurement the day PLR1702 leaves preview. Why nesting is gated at all is in check_complexity.sh's header and Complexity ceilings.
    • PLR1702 pairs with max-complexity = 3 for src/ only. Ceiling 3 alone would admit the nested if/for that ceiling 2 exists to forbid, and PLR1702 alone would not solve the guard-plus-try/except case. Per-tree ceilings live in check_complexity.sh, since per-file-ignores can switch a rule off but cannot set a different threshold.
    • Rules adopted by measurement (ruff 0.11.13), recorded in the Ruff Rule Adoption Log in CONTRIBUTING.md:
      • RET (#426): 0 RET505 and 11 RET501 (a trailing return None in a -> None function), all removed; 5 were reachable from templates/python-common, the other 6 needed a scaffold.
      • A (#418): from re import compile shadows a builtin with no signal today; zero findings across src/ bin/ tests/ optional/. Do not also set [lint.flake8-builtins] strict-checking = true: it enables A005 and fires on utils/typing and chassis/typing, which shadow stdlib typing on purpose as the engine's layout shim (#360), putting a gate violation on correct design and teaching everyone to disable it.
      • BLE (#440): E722 only catches bare except:. Two BLE001 findings, both the _pipeline.py five-mode degradation, now # noqa: BLE001; nine other broad handlers already carried one that nothing enforced. RUF was measured in the same pass and not adopted (150 findings, 138 of them RUF100 unused-noqa), a separate decision.
      • N (#422): 9 findings across 3 rules, adopted with two narrow per-file ignores.
    • Ignored rules. D206 and W191 existed only so the linter did not fight an indent-style = "tab" formatter; #419 moved the formatter to spaces, so neither fires, and re-measuring with both enabled gave zero findings (the 6022 of #222 was measured under tabs). E701 is deliberately not ignored: ruff format expands a compound statement back onto its own line whatever the lint rule says, so ignoring it would be dead config. Reach for the expression form (return not cond, a comprehension, any(...), a ternary). Before suppressing a rule for a style, check whether the formatter already forbids it.
    • dummy-variable-rgx allows an underscore-prefixed name followed by alphanumerics.
    • Banned APIs (TID251). Bare pandas readers are banned so every file or SQL read funnels through utils/tabular_reader, which enforces a FileContract and apply_dtypes; the seam and the tests (round-trip read-backs) are exempt. FileContract is constructed only in config/contracts/; elsewhere both import paths of the class are banned, and a file that imports it for an annotation carries a line-scoped # noqa: TID251. The ORM reference entity was once exempt, but it is the file each tier's CLAUDE.md says to copy per entity, so exempting it exempted the pattern (#172); it now reads through the session and builds its frame with utils.frames.from_records.
    • known-first-party is declared, never inferred, as a superset of every tier's layer names (one that does not exist in a tier never matches). Otherwise ruff guesses, and versions guess differently: a script that puts src on sys.path was sorted one way by the ruff that wrote it and the other by the newer ruff in a generated project, so poe lint modified a fresh tree and the scaffold check failed on the diff with no rule named.
    • max-args = 8, not pylint's 5, by measurement: the reader and mail seams take a genuine spread of options and a config object would only move the arguments. At 5 the gate reported 12 functions; at 8 it reports one, read_table with 11, the widest public API and so the finding worth keeping visible.
    • No identifier-length ceiling (#420), measured and rejected. Over src/ and bin/: 493 definitions, 63 over 20 characters, 4 over 30, none over 40, the longest 34 (assertion_value_or_operator_change); the next-longest in any skeleton is 26. A ceiling at 40 finds nothing, indistinguishable from a gate that never ran. Ruff has no length rule, so it would need a hand-rolled bin/check_*.py, and it would penalise the 3-to-5 character type prefix convention (str_, df_, cls_), pushing authors to drop the prefix or abbreviate the noun. Reopen only if the measured maximum crosses 40, or a concrete defect traces to a name's length.
    • bin/ is linted like the rest (#207). It was excluded for a hypothetical (ruff-format would tabify space-indented helpers and trip E101); the 27 E101s all sat in one genuinely mixed file, and the exclude hid the project's own quality machinery, with 73 findings behind it. Two rules are relaxed there: ERA001 (100% false positives, 0 of 24 true: the gates' long wrapped prose comments contain (, : or = and read as code; per-line noqa would teach authors that noqa is how you write a comment; src/ keeps it, and the global decision is open in #169) and E101 (the 2-space hanging indent of a wrapped Markdown bullet in a module docstring is prose alignment, a tab would break the continuation, and a noqa cannot sit inside a docstring). A src/ module with a numbered-list hanging indent carries the same E101 exemption (#203), and lib-minimal's private-package path mirrors every exemption (* matches the single package segment; without the mirror only that tier goes red, #486).

      • N802 is off in tests/: a mixed-case name where the upper-case word is the point (..._FAIL_rather_than_pass_silently) is the behaviour description tests/CLAUDE.md asks for (5 findings, #422).

    poe_tasks.toml¶

    • It replaced the twin Makefile and tasks.sh, two hand-kept implementations of one command list synchronised by a written rule that had already failed: poe help lacked test_cov_report and test_cov_serve (#189). There is no separate help file: bare poe lists the help = fields, so help and recipe are one declaration. A task without help = is invisible in that listing.
    • Three ways to run a task: poe lint (the dev dependency in .venv, or a pipx install), .venv/bin/python -m poethepoet lint (the module is poethepoet, not poe), and poetry poe lint (only if you installed the plugin yourself). Scripts never hardcode one: bin/poe_exec.sh resolves them in order, as bin/poetry_exec.sh does for Poetry.
    • Tasks run inside the project venv automatically. Poe detects ./.venv, which poetry.toml forces in-project, so a task is a bare command (pytest tests/unit/), never poetry run pytest. bin/poetry_exec.sh survives only for Poetry management commands (update, install --with docs, version), which act on the venv and so route through the Poetry resolver.
    • Bootstrap tasks cannot assume the venv, because they create it: init, ensure_env, venv, precommit, update_venv. Poe is a dev dependency, so it lives inside the venv it would have to create; run bash bin/venv.sh, bin/ensure_env.sh or bin/precommit.sh directly, which is exactly what these tasks call. The shell entrypoint is the second and last interface; do not add a third. init ends a seed step with || true so a missing .env.example aborts only that step, not the venv and precommit steps after it.
    • Do not use [tool.poetry.requires-plugins] to make tasks runnable via poe: it breaks poetry install (#232).
    • bump_version has cz compute the next semver from Conventional Commits, write it to pyproject.toml, regenerate CHANGELOG.md, commit bump: X.Y.Z and create the tag. It passes --no-verify because that single-line message cannot satisfy gitlint's body rule and the format and test hooks are irrelevant to a version bump; run it on a feature branch. It is offline-tier only: the online scaffold strips it, since releases come from release.yaml. changelog previews locally; the published site regenerates it in the docs workflow and CI never commits it.
    • The HTML coverage task covers the whole tree. Never narrow it to --cov=<module>, which reports "no data" on the full suite.
    • There is no test_feat task. Poe passes extra tokens straight through to a task that declares no args: poe unit_tests -k some_keyword and poe unit_tests -x --lf work with no task per flag. Declaring args turns the passthrough off (poe then parses the tokens), as check_commit_msg does, so declare args only for a named, required parameter.
    • System shellcheck and shfmt are optional, for boxes whose venv drive blocks executing the vendored binary; the primary route is the pip dev dependencies. The two single-rule lint tasks are reachable alone so one rule can be checked cheaply; poe lint covers both.
    • check_commit_msg <file> runs only the commit-msg hooks against a message file in seconds, before git commit -F <file>. commitizen and gitlint reject after every pre-commit gate has run, so each rejected message costs a full gate run and the fixes arrive one at a time. It invokes the project's own hooks, so it cannot drift from what the commit enforces. When re-wrapping an over-long body line, re-wrap the whole paragraph (textwrap.fill, width 76); fixing one line by hand pushes the overflow into the next. Poe validates the required argument and prints a real usage line, so the Makefile's hand-written guard was deleted, not ported: a reimplemented check can disagree with the tool.
    • Alembic tasks (#381). Online (upgrade, downgrade) is what a developer runs locally and a deploy runs; offline (--sql) is what goes to a DBA when production access is restricted. db_up already calls alembic upgrade head; these give the individual verbs a place in the command interface. On a tier with no alembic.ini Alembic errors loudly, as db_backup and db_restore do for a non-postgresql backend.
    • The offline wheelhouse tasks (#299): build on a machine with internet access, copy the WHEELHOUSE_DIR payload to the offline target and run wheelhouse_assemble there. See Offline wheelhouse.
    • Two task sets ship conditionally: poe_tasks.library.toml (install_dist_locally, only lib-minimal) and poe_tasks.offline.toml (new_branch, git_merge_to_main, git_diff_*, only when scaffolded without a GitHub remote). The Makefile declared both with -include make/*.mk, whose leading - made a missing file silent. Poe's include is not equivalent: a missing path does not fail but prints Warning: Poe could not include file from invalid path on every invocation (measured), which teaches a team to read past warnings. So the scaffold appends the include list, naming only the fragments it copied (add_poe_include in bin/lib/common.sh); a [tool.poe] table declared after the task subtables is valid TOML and is how the appended block lands.

    .pre-commit-config.yaml¶

    • A default stage is declared. bin/precommit.sh installs both commit-msg and pre-push, and pre-commit applies a hook to every installed hook type unless a stage is declared, so without it every static gate would run twice, on commit and on push. The fast hooks carry no stages: because they belong on commit, and nothing else says that silence also enlists them for the push; hooks that belong elsewhere say so (commit-msg, pre-push, manual).
    • no-commit-to-branch is the online default. Offline scaffolds (no GitHub remote) swap it for the local protect-branch hook via apply_offline_mode, pointing at poe new_branch; online projects also get server-side protection through gh.
    • Whitespace and JSON hooks exclude the verbatim external-byte fixtures (stripping trailing spaces or CRLF would corrupt a captured oracle) and the whole of .vscode/, which is JSONC: settings.json, extensions.json and tasks.json carry comments that check-json rejects.
    • pydocstyle is decoupled from ruff because ruff lacks the DAR-style checks. It selects only D412 and D417 (no blank line after a section header, every parameter documented).
    • One structural gate per doctrine, each a hook and a CI step:
      • check-typing: ruff and mypy cannot assert the presence of a checker metaclass or @type_checker.
      • check-provenance: a module that references read_table must also reference stamp_provenance, so a bronze row never ships without traceability columns.
      • function-length: 60 lines of code. Ruff has no per-function line rule (PLR0915 counts statements) and the docstring is subtracted because NumPy docstrings are mandatory, so a raw span would measure how well a function is documented.
      • docs-boundary: .specs/ is working material and docs/ is published documentation; layout rules are in .specs/CLAUDE.md. The script is BlueprintX's own, copied at scaffold time, so the root repo and a project run one implementation.
      • identifier-masking: a masked CPF or CNPJ compared with a stored unmasked column matches zero rows and raises nothing. Scans .py and .sql, since SQL reaches the database through both.
      • fixture-scope: a proxy, not a detector (#442). The real detector is pytest-randomly (no config; it self-activates once installed); this gate pins today's zero-shared-state baseline so the first scope="module" fixture does not remove it silently.
      • gate-integrity: diff-scoped against merge-base(HEAD, main), unlike every other hook, because it checks a delta: a hook, rule or exclude that was removed without a gate-change-ok: <reason> is a violation (#309). The same script BlueprintX runs over itself.
      • check-all-exports: a package declaring __all__ must name every public member of its submodules. The usual introspective test discovers the family through __all__, so it cannot see a missing member; this walks the files.
      • check-complexity: ceilings per tree (1 for tests/, 2 for src/, 8 for bin/). A test with a branch tests two paths and its green never says which ran. Two ruff invocations, since per-file-ignores cannot set a different max-complexity.
      • one-assert: assertion sites per test_* function; zero fails everywhere and tests/unit/ is capped at one (#544), since a two-assert unit test goes red without saying which behaviour broke. tests/integration/ stays zero-only: one call, several consequences. Blocking since the last split of #544 cleared the unit suites. See tests/CLAUDE.md.
      • check-secrets: gitleaks (#305) is a system binary resolved like shellcheck and actionlint; config is .gitleaks.toml; it skips gracefully locally and hard-fails only when GITLEAKS_REQUIRED=1 (set by CI).
      • check-dtypes: no ingested column typed as a binary float: float64 stores 1984223115.42 as 1984223115.4200000762939453125, an irreversible silent loss. Use list_decimal_cols or text; a dimensionless value opts out with # dtype-ok: <reason>.
      • check-rmw-race: the read-modify-write race (#385), an attribute reassigned from arithmetic over its own value, read by session.get() or .query(...).first()/.one() in the same function, with no with_for_update() and no version_id_col. Two writers can read one value and lose an update silently. A plain read-then-write is not gated. Escape hatch # rmw-ok: <reason>.
      • check-layer-imports: a third-party dependency is reached through a seam in utils/, never imported by model, view or controller. ruff's banned-api is a blocklist and cannot catch a vendor nobody listed; this is deny-by-default per layer. Self-skips when .layer-policy.yaml is absent.
      • check-sql-guards (#355): a WHERE-less DELETE or UPDATE mutates every row with no error, and WITH (NOLOCK) permits dirty reads, both reading as correct code. Escape hatch # sql-guard-ok: <reason>. It scans a .py file (AST) and a raw .sql file under src/config/queries/ (text).
      • check-migration-slugs (#375): migration filenames lead with a known verb (Rails' <verb>_<object>[_<qualifier>]), so ls migrations/versions/ sorts by date and reads as a changelog. Self-skips without migrations/versions/ (only the ORM tier ships them, #373). Escape hatch # migration-slug-ok: <reason>.
      • check-orm-model-guards (#361, the model-side sibling of #355): bitwise &, |, ~ inside .where() or .filter() (Python binds them tighter than ==), two create_all at Base or module scope (the second succeeds having created nothing), and a constraint name= duplicated across a mixin MRO (SQLAlchemy silently overwrites one). Escape hatch # orm-guard-ok: <reason>. Python and SQLAlchemy only; see the gate's module docstring for why each TypeScript/Prisma equivalent does not apply.
      • check-docs-sections: every canonical page (English slug) exists and is registered in mkdocs.yml nav; MkDocs builds an unregistered page anyway, so it silently vanishes from navigation. Keys on slugs, never localised titles.
      • check-docs-code-refs (#159): neither the slug gate nor mkdocs build --strict sees a from x import Y example, so a renamed module keeps being cited after every other gate goes green. Triggers on a docs edit or a src/ move.
      • check-backlog-ledger: a branch whose cumulative diff touches src/ or CI paths must add .specs/backlog/<kebab>_YYYYMMDD_HHMMSS.md with a checklist. It diffs the index against the merge base, so a staged-but-uncommitted ledger counts.
      • check-comment-language: prose for a reader (README, docs/) may be in the project's locale; code, comments, docstrings, symbol names, commit messages and CI output stay English. Prose alone failed: the rule was breached twice in one session, the second time because a sweep grepped only .py and left 55 Portuguese comment lines in src/config/*.yaml, which became the convention the next author copied. Hence every commented file type.
      • check-comment-budget: bounds comment volume in every code format, with QA suppressions exempt through the anticipatory allowlist (bin/comment_budget_allowlist.txt). Escape hatch # comment-budget-ok: <reason>.
    • mypy runs from src/ in the hook for the same reason as in CI; see mypy.ini above.
    • The non-Python lint gates share one wrapper with poe lint (one home, zero drift), and each wrapper skips gracefully when its tool is absent.
    • actionlint beside yamllint: yamllint asks whether the YAML is valid, actionlint whether GitHub will run it. A workflow can be impeccable YAML and be rejected wholesale, which produces no red check: the PR just looks like it is waiting, so a dead gate and a slow gate look the same from outside.
    • deptry requires every package src/ imports to be a direct dependency. Both triggers are needed: a new import in src/ and a deleted line in pyproject.toml break the same rule from opposite sides, and the second leaves src/ untouched. pass_filenames is false because the gate reads the whole manifest.
    • The unit-test hook tolerates pytest exit 5 (|| [ $? -eq 5 ], no tests collected), so a fresh project with an empty suite does not block every commit; exit 1 still blocks.
    • The staged-index guard on pre-push: a non-empty index at push time is the fingerprint of a rejected commit, where the push then ships the previous commit and prints success while the work stays behind. Neither CI (a commit that does not exist is not a diff) nor pre-commit (it already rejected) can see it. It guards the index, not the dirty tree: unstaged edits while pushing are routine, and a noisy guard gets disabled.
    • coverage-floor: fail_under in .coveragerc is honest only if the omit list beside it never widens past a capability's infrastructure/ into domain/ or application/; the gate's module docstring explains the green, silent, wrong failure (#149).
    • Coverage is the slow full-suite gate, so it runs on pre-push and day-to-day commits stay fast. The floor is single-sourced in .coveragerc, read by pytest-cov here and by the CI gate, so there is no duplicated literal to drift.
    • genbadge, not the abandoned coverage-badge, which imports the removed pkg_resources and breaks on setuptools 81 or newer. It generates coverage.xml, then the SVG; the SVG is tracked (README badge) and the XML is ignored.

    Generated-project shell scripts (templates/python-common/bin)¶

    The shell scripts every Python scaffold ships carry no comments. This section records why each is shaped as it is.

    Rules that recur across the scripts¶

    • Resolve, don't install. An optional linter or tool must never trigger an install. A missing tool is a graceful skip on a contributor's machine (exit 0 with a message) and a hard failure in CI, through a *_REQUIRED=1 variable (LINT_ACTIONS_REQUIRED, LINT_DOCKER_REQUIRED, GITLEAKS_REQUIRED). A skip in CI is a gate reporting its own blindness as OK. Applies to lint_shell.sh, lint_yaml.sh, lint_sql.sh, lint_actions.sh, lint_docker.sh and check_secrets.sh; lint_deps.sh and check_complexity.sh are the exceptions that hard-fail, below.
    • Probe with --version, never command -v alone. command -v answers "is there a file by that name on PATH", not "does it run". A shadowing stub, a half-installed package or a binary built for another libc satisfies it, and the wrapper then reports the tool's startup failure as a lint finding: a stub exiting 127 produced actionlint [system]: 7 workflow(s) and exit 127, blaming the workflows (#111). The poetry branch always probed; the system branch now does too.
    • Assert the discovery count. Tools such as actionlint and deptry exit 0 when handed nothing, so a wrapper whose glob matched nothing reports success forever. Zero discovered files fails (lint_actions.sh, lint_deps.sh, check_unix_filenames.sh, check_complexity.sh); lint_docker.sh is the one deliberate exception, below.
    • Group a find expression. -name '*.yaml' -o -name '*.yml' -type f parses as (-name '*.yaml') OR (-name '*.yml' AND -type f), so a directory named *.yaml enters the list and fails the gate for an unrelated reason. The \( ... \) is load-bearing. A prune group must also come first with no test before it: a leading -type f is false for a directory, so -prune is never evaluated and .venv and node_modules get linted (check_unix_filenames.sh, measured).
    • mapfile < <(producer) discards the producer's exit status. A find, git or gh api that dies midway hands over a partial or empty list that reads as complete, and the script announces "clean" over a query that never ran. Materialise to a temp file first (also because a bash variable cannot carry NUL bytes), check the status, then read (lint_docker.sh, check_unix_filenames.sh, rerun_stale_gate_runs.sh).
    • Never set a global inside $(...). resolve_poetry populates the POETRY_CMD array; command substitution runs in a subshell, so the caller's array stays unset, every later run_poetry fails and, with output suppressed, the gate reports a clean tree having run nothing: 79 known violations reported as success (check_complexity.sh, lint_deps.sh).
    • Capture an exit status where it is produced (|| int_status=$?). A bare call is exempt from set -e only because a caller three levels up happens to suspend errexit, which is true today and not something anyone should have to know.
    • Keep a command's output when you explain its failure. Never >/dev/null 2>&1 a command and then blame a cause: the explanation becomes a guess about text you refused to read. Remedies name the resolved binary (${POETRY_CMD[*]}), never a bare poetry (export_deps.sh, enable_repo_rules.sh).
    • Verbatim wrapper discipline. Each wrapper keeps the heavy logic out of heredocs: a heredoc is for inert text a script emits, not a program (bin/CLAUDE.md). The CA union and the pip requirement translation were python - <<'PYEOF' blocks of 66 and 151 lines that ruff never linted, mypy never checked and pytest could not import; they are lib/ca_bundle.py and lib/pip_requirements.py now, with the interface unchanged.
    • Sourcing lib/bootstrap.sh does no work. It defines functions only; the caller invokes bootstrap_init and then the helpers it needs. It guards against being sourced twice.

    GitHub setup scripts (enable_*.sh)¶

    • Why they exist. A workflow's GITHUB_TOKEN is an App installation token that cannot create a Pages site, change its source, set a ruleset or flip a security toggle ("Resource not accessible by integration"). Those need repo-admin rights, which a maintainer running poe init has through gh auth and CI does not. Merge protection kept in a maintainer's memory is protection a fresh clone or fork silently lacks. All are idempotent and non-blocking: gh absent, unauthenticated or not admin warns and returns 0 so init completes.
    • enable_pages.sh. Two models, auto-detected from mkdocs.yml. With provider: mike the release workflow deploys to gh-pages, so Pages serves from that branch, flipped only once the branch exists (the first mike deploy creates it) so the live site never points at an empty branch. Without mike, docs.yaml deploys through actions/deploy-pages, so the source is "GitHub Actions" (build_type=workflow). The two models are mutually exclusive.
    • enable_security.sh. The Settings checkboxes are not reproducible and are forgotten on a fork. Three plain PUTs (204): vulnerability alerts, then automated security fixes (which depend on alerts being on), then private vulnerability reporting, the intake channel SECURITY.md points at. Secret scanning and push protection are one PATCH of security_and_analysis with scanning first (push protection depends on it, and fields apply in order); free on public repos only, so on a private repo it warns and continues. Automated security fixes are for vulnerabilities, .github/dependabot.yml for ordinary version updates. GitHub detects a root SECURITY.md by itself. GitGuardian (#155) was evaluated for this role and deferred: the native toggles are free and need no third-party app on public repos; reconsider for private repos or an offline pre-commit scanner. secret_scan.yaml is a separate, opt-in decision made at scaffold time (#287), not here: poe init runs against an already-created repo, the wrong phase to gate a file's shipping. A self-audit of BlueprintX (#164, 2026-09-04) found no divergence; the script has no verify mode.
    • enable_repo_rules.sh. Applies the pr-quality-gate ruleset by name (PUT when it exists, POST when it does not; never a blind POST, which would duplicate it):
      • pull_request with required_approving_review_count: 0 and required_review_thread_resolution: true. Zero, because GitHub forbids authors approving their own PR, so any higher value locks a solo maintainer out; zero still forces every change through a PR, which is the guardrail.
      • code_scanning (CodeQL, alerts at high_or_higher), non_fast_forward, deletion.
      • copilot_code_review is its own rule type: the intuitive pull_request.parameters.automatic_copilot_code_review_enabled returns HTTP 422, which makes the feature look UI-only. The automatic/manual boundary is repo config versus account plan: without a qualifying Copilot plan the rule sits correctly configured and inert, with no error. gh api user/copilot_billing 404s for a personal account even when Free is active; read the plan page.
      • Deliberately not enabled, each a second source of truth: "Require code quality results" (subjective AI severity on the merge path) and "Restrict code coverage" (the floor is single-sourced in .coveragerc).
      • Settings the gate cannot set itself: code-scanning default setup, allow_auto_merge (without it the enablePullRequestAutoMerge mutation silently no-ops), delete_branch_on_merge and the do-not-merge opt-out label. Each is read back, since a green API call is not proof the mutation took.
      • required_status_checks only when the list is non-empty, because a required check that never reports blocks every PR forever. Do not guess names: they must match check-run names exactly (matrix values included); take them from a real PR with gh api repos/:owner/:repo/commits/<sha>/check-runs --jq '.check_runs[].name' | sort -u. The seeded entry is the review_threads.yaml job name, correct by construction and reporting on every PR from the moment it opens. A name qualifies only if it is a literal jobs.<id>.name: of a workflow the project ships, its on: pull_request has no types:/branches:/paths: filter, no job-level if: can skip it, and the workflow is shipped; tests.yaml fails the second rule and coderabbit_trigger.yaml the third. The list is data (bin/required-checks.txt, per template family, #164/#564), compared verbatim (stray space never matches). An empty list means CI runs on every PR and blocks nothing: measured on BlueprintX 2026-08-16, a PR merged with 32 of 47 checks passed.
      • A missing required-checks.txt is unknown, not an empty list (#585): it must not drive a PUT against an existing ruleset, which would silently strip its required_status_checks.
      • REVIEW_THREADS_REQUIRE_RESOLVED=1 (#196) supersedes the earlier delegation of the resolve half to the ruleset, which drops a thread marked isOutdated; see the records above. The accepted cost is a red check after a resolve until a re-run.
      • strict_required_status_checks_policy must be true (#307, "Require branches to be up to date"). With it false a PR merges on a green run against a base that no longer exists (#302: six tier checks red only because #293 had not merged; a rebase fixed it). The cost is an update-branch for a PR whose base moved, the accepted trade.
      • The summary reads the server back, not the input: a provisioning step that reports its own input verified nothing. The strict check has three states with one exit contract (#311): 0 confirmed strict, 1 confirmed not strict, 2 absent or unreadable. "Could not check" and "checked and it is fine" must never share an exit code, a failed read is never an empty answer, and an absent policy reads back as jq null, which is unknown, not a violation. init swallows non-zero with || true; verify is the read-only CI guard (needs no admin) and fails loud on 1 and 2, requires at least one mechanism to confirm strict, and checks classic branch protection too, since BlueprintX's own main uses it. The default branch read has no || echo main fallback (CWE-693): a substituted answer nobody confirmed lets verification inspect the wrong branch.
      • Apply errors keep the API's own words; the old form swallowed stderr and blamed admin rights for a malformed payload. ~DEFAULT_BRANCH survives a rename.

    Linting wrappers¶

    • lint.sh is the one list of every gate, called by poe lint, CI and bin/ci/scaffold_lint_test.sh. It replaced 14 inline recipe lines duplicated across two files that had already diverged (#189). Order is load-bearing: the two ruff steps come first and mutate the tree (--fix, then format), so every later gate judges the tree CI checks; poe lint must leave a clean checkout unchanged, and a diff means a gate and the formatter disagree. set -e with no masking: do not add || true. mypy runs from src/ (config path ../mypy.ini) so src is the single package base. check_provenance was the one gate CI ran and this script did not, so "green locally, red in CI" was reachable on the gate that stops an ingested row shipping without its url and updated_at columns.
    • lint_shell.sh resolves shellcheck and shfmt preferably through the Poetry venv, which finds the vendored wheel wherever the venv lives, including a Windows UNC or mapped drive; a bare-PATH lookup would silently skip both there. It falls back to a system binary (install_shell_linters.sh) and skips only when neither exists. Default mode formats in place; --check is shfmt -d for the hook. The canonical gate is warning-and-above with SC1091 excluded (siblings are sourced by runtime path). File discovery is find-only: a literal tasks.sh was left beside it after the poe migration and made shellcheck report "does not exist" for the whole run.
    • install_shell_linters.sh is an optional convenience for machines that need a system binary (a venv on a share that blocks executing the vendored one). Each branch is guarded with command -v and skips with guidance; it never hard-fails. Order by OS: Windows chocolatey then scoop (both package shellcheck and shfmt), macOS brew, Linux apt-get, dnf, pacman, zypper (shfmt is rarely packaged, so it stays on the pip shfmt-py or go install). --dry-run or DRY_RUN=1 previews through one guarded runner.
    • lint_yaml.sh, lint_sql.sh resolve Poetry through the bootstrap lib (poetry, then python -m poetry) rather than a bare command -v poetry, which saw only a bare poetry and silently skipped a python -m poetry-only box. yamllint's real status propagates. One sqlfluff pass covers every engine: queries live in src/config/queries/<engine>/, sqlfluff resolves config per directory, and adding an engine is adding a folder, never a second pass with another --dialect or a dialect in the filename.
    • lint_actions.sh exists because yamllint asks whether YAML is well-formed and actionlint asks whether GitHub will run it. A workflow that added pull_request_review_thread (a real webhook event, not a workflow trigger) was impeccable YAML, passed every hook, and GitHub rejected the entire file with no red check: the PR just looked like it was waiting, so a dead gate and a slow gate are indistinguishable. In CI the binary is installed at a pinned version with a verified SHA-256 and LINT_ACTIONS_REQUIRED=1 makes absence a failure. It sets shellcheck options for the run: blocks actionlint shells out to, so one script does not pass one gate and fail the other. A comment line may not start with a tool's name, because it parses as a lint directive.
    • lint_docker.sh is a wrapper, not a line in lint.sh, because hadolint is the only gate with no Python package: pre-commit runs hadolint-docker, which needs a Docker daemon, and calling that from poe lint would turn a lint run into an infrastructure requirement. It differs from lint_actions.sh deliberately: zero Dockerfiles is legitimate (no Python tier ships one, measured 2026-08-23; the only one is in react-spa-webpack). The rule is: no Dockerfile skips; Dockerfiles with no tool skips unless LINT_DOCKER_REQUIRED=1; both present lints. The count is asserted before the tool runs, so hadolint is never handed an empty list. The image is pinned by digest, not tag: the tag pins what is asked for, the digest what arrives, and the image is pulled and executed on the gate's machine (re-resolve with docker buildx imagetools inspect hadolint/hadolint:<tag>). It probes docker info, since the client binary is present on machines whose daemon is stopped. The tree is mounted read-only and the run happens inside it, so hadolint finds .hadolint.yaml and reports file names (stdin reports -); --no-fail is not passed, the container's status is the verdict.
    • lint_deps.sh (deptry over src/). The rule "every imported package is a direct dependency" was written down and nothing checked it. The first run found both DDD tiers using pandas in five src/utils modules while declaring it nowhere (it arrived through wwdates); a calendar library dropping pandas would have broken every DDD project with an ImportError nobody could predict. It must run inside the project venv with no system fallback: deptry maps a module to its distribution through the metadata of the environment it runs in, and outside the venv the verdict inverts (9 findings on ddd-native, all false and two contradictory, while both real defects vanished). The config lives in pyproject.toml per tier, never a shared deptry.toml: --config <file> re-points deptry at that file as the manifest too, and it fell back to requirements.txt and relabelled beartype, python-dotenv, wwdates and every DB driver as transitive. bin/ is out of scope, since one run cannot hold both profiles and each dev dependency would become a DEP004. Zero .py files under the tree fails.
    • check_unix_filenames.sh rejects names outside [a-zA-Z0-9._-]. It has two callers: pre-commit passes staged files, and poe lint/CI pass nothing, in which case it discovers the tree itself with git ls-files -z (respecting .gitignore) and a find fallback for a scaffold not yet git init'd. The no-argument mode exists because the old script iterated an empty $@ and printed "All filenames are valid" having examined nothing. Zero discovered files is never legitimate there, so it fails.
    • check_secrets.sh (gitleaks, #305). GitGuardian (#155, #286) is the hosted product and BlueprintX's own GITGUARDIAN_API_KEY measurably fails auth (exit 3); live detection there was never proven. This repo is public, so shipping that key would either hand strangers the maintainer's quota or ship every project red. gitleaks needs no key or account, so it is the default scanner, additive to GitGuardian. One implementation: bulk-copied into every project and run by BlueprintX's own hook and workflow through --root .. Config is gitleaks' own: .gitleaks.toml at the root of the target. Resolve, don't install; GITLEAKS_REQUIRED=1 in CI. Exit 0 or 1 are data and drive the script's exit.
    • check_complexity.sh. The per-tree ceilings and their arguments are in Complexity ceilings; the points that live in the script are:
      • Cyclomatic ceilings are tests 1, src/ 2, bin/ 8: a branching test tests two paths and its green never says which ran; branching that is the work of a validator or parser takes the escape hatch with a reason; the gates in bin/ are parsing tools by nature and at 2 they were 74% violating, a number nobody pays and so a gate nobody keeps. Nesting depth (PLR1702) is a separate table: tests 2, src/ 3, bin/ 5 (findings at one ceiling lower: 2, 54 and 16 for tests, src/ and bin/). An earlier revision asserted 1, 1 and 3 by analogy to the mccabe row; all three were wrong, and because the hook scans the whole tree each blocked every commit. An argument by analogy is not a measurement: mccabe counts branches and PLR1702 counts nesting. These are the zero-cost ceilings; the tighter ones (src/=2 costs 8 fixes, bin/=4 costs 2) are each their own measured slice.
      • Do not reimplement mccabe. ruff ships it as C901 and PLR1702; a draft counter that treated assert and with as decision points reported 85% of tests/ violating where the real figure was 8%. A threshold agreed against one implementation and enforced by another is not the threshold anybody agreed to.
      • Two ruff invocations per rule: per-file-ignores can switch a rule off for a path but cannot give it a different threshold, so run_ruff_check takes the rule code and its config key (lint.mccabe.max-complexity, lint.pylint.max-nested-blocks) as arguments.
      • Escape hatch: # complexity-ok: <reason> on the def line (ruff anchors both rules there, not on a decorator), reason required, one marker for both rules. The whole signature is scanned, because ruff format re-wraps a long signature and moves a trailing comment to the closing-paren line; a hatch correct on the def stopped counting when the formatter touched the file (CreateLog._validate_path). The formatter wins, so the gate adapts. The signature scan is bounded so a malformed file is not turned into a file read.
      • Only --root is accepted, so BlueprintX runs this file over its own tree (#189).
      • ruff is probed with --version so a real lint exit code is never mistaken for "absent". The mode is set as a global, never printed for $(...), for the subshell reason above. ruff exits 0 or 1 (data); anything else means it could not run and its output is re-printed. Output goes to a file, not while read < <(...): a process substitution runs in a subshell, so a hard failure could only exit that subshell, the loop would read nothing and the gate would be blind a second time.
      • Colour: ruff wraps every path:line:col: separator in ANSI escapes when colour is on, and those travel into cut -d: and an arithmetic expansion, which dies with [0m101[36m: syntax error: operand expected, naming neither ruff, colour nor this gate (6 of 6 tiers red on 2026-08-23 because a shell exported FORCE_COLOR). NO_COLOR=1 alone does not fix it: with FORCE_COLOR=3 also set ruff still colours, and TERM=dumb does not change that. So the forcing variables are unset, in a subshell rather than env -u (the poetry branch calls a shell function env cannot exec) and rather than local (does not hide an exported global from a child). NO_COLOR stays as belt-and-braces.
      • ruff absent is not a graceful skip: it is a declared dev dependency, so its absence is a broken environment. A broken glob would otherwise report success forever.
    • test_urls_docstrings.sh (hook) scans docstrings for URLs, cached for a week to avoid repeated network calls. Domains that answer a scripted probe with 403 or anti-bot pages regardless of method are treated as reachable, a deliberate false negative: the alternative is a permanently red hook that people learn to bypass. Match the hostname, never a substring: *domain* would allowlist https://attacker.example/path/openai.com and https://openai.com.attacker.example/; strip scheme, userinfo and everything from the first /, ?, # or :, then require an exact match or a real subdomain. Probes go HEAD, then GET for servers that refuse HEAD, then wget for servers that refuse curl; each fallback exists for an observed failure, so the order is load-bearing. State is script-scoped because bash cannot return an associative array. A host-only URL is skipped (nothing to 404, and fetching it only rate-limits). A one-line docstring opens and closes on the same line and must not flip the state. A delimiter line is docstring content and is scanned before the state flips (#206, #224): the old continue blinded the gate on """One line https://...""" and on the opening line of a multi-line docstring, and was self-concealing, since an unscanned URL is never fetched or cached. A closing delimiter sharing a line with text was never blind (the URL was scanned as body text) but the state never flipped back, so every later line was read as inside the docstring and over-scanned; both delimiters are now matched wherever they sit.
    • check_clean_index.sh (pre-push). A non-empty index at push time is the fingerprint of a commit rejected after git add: the push ships the previous commit and prints success while the work stays behind, found only by comparing HEAD to origin/<branch>. No other layer sees it: CI sees only what was pushed, and pre-commit already did its job by rejecting. It also closes a hole a written rule did not: "never pipe git commit through tail/grep; confirm HEAD moved" existed and was violated hours after being quoted, because a rejection scrolling off screen is what a tired reader misses. It guards the index, not the dirty tree: unstaged edits while pushing are routine, a noisy guard gets disabled, and a populated index is nearly false-positive-free. Escape hatch: git push --no-verify or stash the index. With no work tree (a shipped zip) there is nothing to guard and it never blocks.

    Bootstrap, runtime and CI helpers¶

    • lib/bootstrap.sh. ensure_python_version prefers pyenv (pinning the project version) and falls back to the system interpreter with a version-mismatch warning for corporate hosts that forbid pyenv. to_native_path turns /a/foo/bar into A:/foo/bar through cygpath on Git Bash/MINGW, shell-only and stripping stray CR and LF; POETRY_CMD is an array so a python -m poetry fallback stays quotable. build_union_ca_bundle writes bin/ca_bundle.pem as the union of certifi's roots, whatever bundle the host provisions and the corporate CA. Union is the point: pointing SSL_CERT_FILE, REQUESTS_CA_BUNDLE and PIP_CERT at the corporate CA alone narrows trust to one certificate and breaks every connection not through the proxy's CA (Poetry went from "0 candidates" to "All attempts to connect to pypi.org failed" because the helper ran), and it clobbers a bundle a corporate image provisions. A generated file also replaces the old append to certifi's cacert.pem, which mutated site-packages invisibly and was undone by any reinstall. wire_corporate_ca is a no-op without bin/corporate_ca.pem, so non-corporate setups keep full verification; it resolves the absolute Windows-safe path in shell, exports the union to every consumer, points Poetry's resolver at it best-effort, and deliberately does not export PIP_TRUSTED_HOST, which disables verification for PyPI outright.
    • get_corporate_ca.sh generates bin/corporate_ca.pem from the OS trust store without touching the network or disabling TLS verification. It is the store the browser uses, which is why the browser works behind a TLS-inspecting proxy while pip, with certifi's own bundle, does not. On Windows it reads the store from Python directly, with no admin rights. On Linux/macOS the store is already a file and a corporate image normally installs the CA there, so it refuses with instructions rather than guess a path or capture whatever certificate the network presents. The pem is git-ignored and picked up by poe venv and poe run.
    • lib/pip_fallback.sh. Every status is checked: the function used to return the pruning status, which succeeds on an empty file, so a failed TOML reader or emitter produced an empty requirements file and reported success, and install and verify both accept zero requirements (the venv was declared good having installed nothing). _read_env_var is anchored to the project, since its default .env is CWD-relative and reading the wrong one prunes the driver the project needs. Pruning: the service tiers declare all four DB drivers unconditionally (about 20 MB of pyodbc, oracledb, psycopg and mysql-connector a SQLite project never imports), and on a corporate index that answers 403 per package an unrequested dependency is a self-inflicted failure surface (2026-08-16, mysql-connector-python was refused and took the whole install down). DB_BACKEND is lowercased to match config/connection_db.py (os.getenv("DB_BACKEND", "sqlite").lower()), or PostgreSQL would drop psycopg. A driver not in the table is not a DB driver and is never pruned. pip install -r is atomic, so one refused wheel discards a batch whose other packages downloaded; the batch is only the fast path, and on failure it retries per requirement so everything installable is installed and the report names every refused package. A blocked index can report success with nothing usable (already satisfied without contacting the index), so the last word is a real import against the target venv's own interpreter (verify_venv_imports.py).
    • lib/common.sh is kept byte-identical in templates/common/bin/lib/ and here (CI enforces parity; offline scaffolds copy the common version over this one, so both carry resolve_default_branch and _read_env_var). print_status <level> <message> (success, error, warning, info, config, debug, section) sends errors to stderr and tees timestamped lines to $LOG_FILE when set. An unknown level names the bad status on stderr instead of printing an unmarked line: 35 calls spelled warn for warning across five scaffolds each rendered a warning like ordinary chatter. resolve_default_branch: explicit argument, $DEFAULT_BRANCH, origin/HEAD, local main, else master. _read_env_var NAME reads .env (override with ENV_FILE), returns the raw right-hand side without stripping an inline #, so passwords with # or $ survive (the point of bypassing Make's expansion), removes one pair of surrounding quotes, last assignment wins, missing file or key is empty. ensure_dir checks existence before mkdir -p: over an existing path on Windows mapped or UNC drives a bare mkdir -p can fail with "Permission denied".
    • poe_exec.sh and poetry_exec.sh are the single Poe and Poetry entrypoints for every hook, workflow and script, so nothing depends on a bare binary on PATH. Poetry may be reachable only as python -m poetry (the user-scripts directory is not on PATH on Git Bash/MINGW), so a bare poetry run dies "command not found" with Poetry installed; resolve_poetry() tries bare then $PYTHON -m poetry, and ensure_poetry() installs from requirements.txt when none resolves. Poe reaches a machine by three routes: the in-project .venv first (load-bearing: poetry.toml forces in-project, poetry install does not put poe on PATH, and $PYTHON is the system interpreter, so in CI after poetry install --with dev neither later route can see it), then poe on PATH or $PYTHON -m poethepoet (the module is poethepoet, not poe: python -m poe fails), probed by running the module because a pip install --user layout puts the package where the interpreter finds it but the console script nowhere useful, then poetry poe last. The plugin is no longer declared: a project-scoped [tool.poetry.requires-plugins] breaks poetry install (a plugin env keyed by project name, not path, measured), it is the slowest route, and poe's docs advise against it because Poetry's CLI mangles arbitrary task arguments and the plugin silently disappears if --no-plugins appears anywhere. Stdout discipline: resolution status goes to stderr so the task's own stdout and command substitution (version -s) stay clean. Zero arguments is valid and is the help path.
    • precommit.sh installs commit-msg and pre-push hooks. pre-commit install needs git and a work tree; a deploy box (a shipped zip) has none and pre-commit aborts "FatalError: git failed", taking init down. Hooks are dev-only, so with no work tree it warns and skips, like the best-effort ensure_env and the Playwright install. Opt-in alternative: replace the skip with a loud git init, announced so a dev box surfaces a lost .git; never auto-init silently. On a shared network checkout (Windows UNC mapped to a drive) the first person to check it out owns it and any other domain user trips git's "dubious ownership" guard, which blocks every repo operation and makes pre-commit install die too. ensure_safe_directory registers a per-user safe.directory before the work-tree probe, which would otherwise fail under the guard and wrongly conclude "no repo" (a bogus git init over an existing tree). It lifts git's own suggested path rather than reconstructing it, and strips the UNC quote.
    • venv.sh, run.sh. run.sh resolves the entrypoint, ensures a venv, prefers Poetry and falls back to stdlib venv plus pip requirements; the pinned interpreter is selected first so both branches use it. Tokens after the entrypoint are the user's argv: poe run backfill forwards backfill, and dropping it makes main.py fall back to PIPELINE_INTENT (#317). The Playwright install in venv.sh is best-effort and never aborts init: it warns and points at poe fix_playwright, since the environment is usable without browsers and playwright install fails on hosts without a compatible toolchain (Error: spawn UNKNOWN under Git Bash on Windows). --with-deps installs apt packages and is valid on Debian and Ubuntu only, so it is added on Linux only. fix_playwright.sh cleans and reinstalls the browsers.
    • ensure_env.sh seeds .env from .env.example when .env is absent; if the template is missing it reports and aborts that script with non-zero, and the task runner ignores that failure so the venv and pre-commit steps still run. db.sh has up (idempotently start services, ensure schema, migrate), backup (dump to BACKUP_STORE_PATH) and restore (DUMP=<path>); Poetry is resolved robustly because a bare poetry may be absent.
    • export_deps.sh writes requirements-lock.txt for hosts that can pip install -r but not Poetry (locked-down boxes, slim containers, air-gapped transfers). export is a plugin subcommand, so the question is "does the Poetry that resolves here carry the plugin?", and a pip install --user Poetry and the venv's Poetry report the same --version with different plugin sets. That is why the plugin is pinned in requirements.txt (what ensure_poetry installs from) and not only as a dev dependency, which reaches the venv and nothing else: the recipe would work from an activated shell and fail from a VS Code task, cron, CI and the offline host it serves. The artifact path is overridable so a test can redirect it.
    • test_cov.sh is four steps that only make sense in order: pytest writes .coverage, coverage report prints it, coverage xml serialises it, genbadge renders coverage.svg. Splitting them across two recipe files put the order in two places. genbadge runs with --local: a build step that reaches the network fails behind a corporate proxy and on an air-gapped runner, and a badge is not worth either.
    • build_wheelhouse.sh (#299, pieces 1 to 3 of #127). A corporate machine behind a TLS-inspecting proxy that blocks PyPI cannot install anything; verify_venv_imports.py makes that failure loud and this is the remedy: poe wheelhouse builds the payload on a machine with internet and poe wheelhouse_assemble rebuilds it on the offline target. See Offline wheelhouse. Heavy logic (marker evaluation against a target environment, zip/split/manifest, verify-and-refuse) is in lib/wheelhouse_select.py; the shell owns only network I/O and orchestration. The default destination is a sibling of the repo: outside it, never a git add candidate, surviving a re-clone, per repo because sibling projects pin different versions. DB-driver pruning by DB_BACKEND took 65 MB to 45 MB (#299). Bash 3.2-safe (macOS system bash): no associative arrays, no ${var,,}; mariadb shares mysql's driver. Cross-platform builds pass pip's own platform tags verbatim (win_amd64, manylinux2014_x86_64); unset, pip downloads for the build machine. The trap expands dir_tmp immediately: single-quoted it would hit an unbound variable under set -u after the function returned, leaking the directory and exiting non-zero.
    • pr_reconcile.sh (#255) is the mechanism extracted from the pr-reconcile.yaml inline run: block so every workflow that ships it invokes one implementation, like check_review_threads.py and rerun_stale_gate_runs.sh. Inputs: GH_TOKEN and GH_REPO (required), EVENT_PR (one PR, the fast path) and SWEEP_LIMIT (default 30, the scheduled backstop). It acts only on a merged PR, so a closed-unmerged PR closes nothing. A linked issue's repository travels with its number: a cross-repo link would otherwise resolve gh issue view 42 against GH_REPO and close an unrelated #42 there, silently. It closes only issues still open, and deletes only a same-repo head branch, and only while the ref still points at the commit the PR merged: this runs on a schedule, possibly days later, and a branch name is reusable (fix/thing cut again for new work would be deleted with unpushed commits, reporting success). An already-deleted branch is a no-op.
    • rerun_stale_gate_runs.sh re-runs the stale failed runs of the review-thread workflow that still poison the merge rollup. The gate re-triggers on pull_request, pull_request_review and pull_request_review_comment, each creating a new check run, and branch protection reads the aggregate, so the push-time failure keeps the PR BLOCKED however many later runs pass (#262 one stale failure, #264 five, #265 seven; gh run rerun <id> --failed on only the stale failures flipped each to CLEAN). concurrency: was tried and is strictly worse: a queued run cancelled before it starts publishes no check run, leaving the required context at Expected — Waiting for status to be reported, which no re-run clears; a stale red is at least clickable. It exits 0 even when it cannot do its job, and that is not failing open: it is a janitor, if it fails the run stays red and the PR stays blocked (the status quo, visible), whereas failing the step would deposit one more failed run into the rollup it came to clean. It reports through one seam that emits both the ::warning:: annotation (a machine-read workflow command that puts the message in the run summary) and the status line, because three copies of that pair are where one loses its annotation. It refuses to act outside a pull-request run (an empty HEAD_SHA is ordinary on other events). It asks the API which workflow the current run belongs to, since the two shipped copies disagree on name and filename (.yml here, .yaml in a generated project). It scopes by head_sha so older commits' genuine failures are untouched, and skips $GITHUB_RUN_ID, the loop guard: it only runs on a successful run, so re-running itself would re-run a green run forever. Needs actions: write.

    Root workflows: why each is shaped as it is¶

    These records explain the GitHub Actions workflows under .github/workflows/ in this repository. They were moved out of the workflow files, which now carry no prose.

    coderabbit_trigger.yml — a user PAT asks for the review¶

    • Why the workflow exists. CodeRabbit declines automatic reviews on a repository with fewer than 10 stars, and the threshold is not configurable from .coderabbit.yaml. The consequence was PRs #204 and #213 merging with every check green and no review.
    • Why a PAT and not GITHUB_TOKEN. CodeRabbit ignores bot-authored comments. A comment posted with GITHUB_TOKEN is authored by github-actions[bot] and was dropped silently (measured on #210: no reply in 5 minutes). A comment from a user PAT replied in 9 seconds (#215). Do not simplify this.
    • The secret is GH_PAT_REVIEW_TRIGGER. The earlier name CODERABBIT_TRIGGER_PAT read as a CodeRabbit key and cost two rounds of 401 Bad credentials. Actions reserves the GITHUB_ prefix (HTTP 422), so GH_ is the closest legal spelling. Setup: a fine-grained GitHub PAT for this repository with Pull requests: Read and write, then gh secret set GH_PAT_REVIEW_TRIGGER --repo <owner>/<repo>.
    • Fail, never skip, when the PAT is absent. A skip would reproduce the original defect: no review and nothing says so. A fork PR gets no secrets and lands in the same failure, correctly.
    • The shape check. A bare 401 cannot tell a wrong token from a token stored wrong (gh secret set … < file keeps the trailing newline). The step reports only the token class and booleans, never a value, a substring or its length, because the logs are public and a substring of a masked secret is not masked.
    • A 403 is a different failure. It is GitHub's API rate limit for the PAT's user, not CodeRabbit's review quota, and clears by itself; it must not read as a bad token. Match on rate limit alone: the secondary limit's wording ("You have exceeded a secondary rate limit", 403 or 429) does not contain the primary's phrase.
    • Triggers. synchronize was dropped in #454: only 5.4% of 773 post-open events produced a finding and 69.6% were rate-limit notices, and the required "Review threads answered" check already closes the unreviewed-merge hole. opened was kept in #567: asks on open are 45% of all spent but win 26% of reviews, yet they enrol the PR for retry_rate_limited_review.py, which only adopts a PR whose newest reviewer comment is a rate-limit notice. Dropping it would leave a PR opened with no session running stalled. Drafts are skipped; ready_for_review brings them back.
    • Concurrency may cancel here. Several pushes need one trigger, and this workflow publishes no verdict anyone waits on, unlike review_threads.yml.

    review_retry.yml — retry a rate-limited review on a timer¶

    • It does not relax the gate. Of 112 PRs, 19 hit a rate limit and 18 were reviewed in the end, so a rate limit is a delay and the asking is automated. The 19th (#157) merged with no review while a notice stood, which is the hole the gate exists to close.
    • A schedule is the only shape that works: nothing fires while a PR waits. Measured windows are 10 to 25 minutes, so */10 clears most on the first tick after the window.
    • It needs the user PAT for the same reason as the trigger. The script reads back the comment's author type and warns if it posted as a Bot.
    • It asks at most one PR per run, oldest first (#280), which matches the shared account's roughly one review per hour.
    • It has no secret-shape preflight: with a missing PAT the gate still blocks the PR visibly, and a job failing every 10 minutes would be noise.
    • Its concurrency group has cancel-in-progress: false so a queued run waits and re-reads the comments. That does not contradict the no-concurrency rule below: it is a janitor that publishes no required check.

    review_threads.yml — triggers, concurrency and the stale-run cleanup¶

    • Triggers are the point. Under pull_request the verdict was computed at push time and went stale when a review landed (PR #180 merged with two unanswered threads). pull_request_review and pull_request_review_comment re-run it. pull_request_review_thread is a webhook event, not a workflow trigger; adding it makes GitHub reject the whole file silently (#156), and bin/ci/check_actions.sh now catches that class.
    • issue_comment is load-bearing. A clean CodeRabbit review is a plain issue comment, so without this trigger the gate stays frozen on its push-time failure (measured on #342: the gate was wrong two seconds after the review finished). The job skips plain issues, and reads the PR number from issue.number on that event.
    • Resolution cannot re-trigger it. Resolving a thread emits no workflow trigger, so after a resolve the run must be re-run once. The job asserts both halves (reply and resolve, REVIEW_THREADS_REQUIRE_RESOLVED=1) since #196; the earlier split gave the resolve half to required_conversation_resolution, which drops an outdated thread from the blocking set (#193: merge enabled, thread unresolved and outdated, 29 of 29 checks green).
    • It is safe to require. The earlier note that it must not be a required check was wrong and left required_status_checks empty, so a PR merged with 32 of 47 checks passing (#173 and PR 185).
    • No concurrency: block, deliberately. With cancel-in-progress: false only one run may sit pending, so each queued run cancels the waiting one (10 runs in 25 seconds on #216). A run cancelled while queued publishes no check run, leaving the required context at Expected — Waiting for status to be reported, which nothing clears.
    • The stale-run cleanup (#263). Each trigger opens a new check run and branch protection reads the aggregate, so a correct push-time failure keeps the PR blocked behind any number of later passes (5 on #264, 7 on #265). The Clear stale failed runs step re-runs those failures. if: success() is the loop guard. On issue_comment the head SHA must be fetched because the event has no pull_request object, and an unresolved head fails loudly (#350).
    • Closing the ceiling properly would need a webhook receiver or a GitHub App dispatching repository_dispatch on resolved. That was rejected as not worth an always-on listener for this repository.
    • Its own workflow. It is kept out of scaffold_checks.yml so a review comment does not re-run the 29-job scaffold matrix: one job, a few seconds, as often as needed.
    • A finding takes both halves: reply with what changed and why, then resolve. A bot resolves its own threads on seeing the fix, so isResolved records the reviewer's satisfaction, never the author's reasoning.

    Other workflows¶

    • behind_base_gate_report.yml (#368). A PR runs every gate from its own checkout, so a branch behind main can fail or wrongly pass on an old gate. gh pr update-branch moves the head commit and can supersede a clean review, so the workflow only reports. Its schedule is coarse: a */10 schedule fired 6 times in 21 hours on this repository.
    • pr-reconcile.yaml (#255). A PR merged by native auto-merge armed with github.token leaves the linked issue open and the branch undeleted, while a manual merge of the same PR closes it. The pull_request: [closed] path is an optimisation; the schedule path is the backstop and the fix, because scheduled events are exempt from the "no new workflow runs" suppression. It calls templates/python-common/bin/pr_reconcile.sh, the same script a generated project calls at bin/pr_reconcile.sh.
    • issue_scope.yml. Its own workflow so an issue edit re-runs one job instead of the scaffold matrix. It listens to issues events because an edit changes the declaration the gate judges against, and checks out the base commit, never the merge ref, so a PR cannot rewrite check_issue_scope.py and judge itself. The only writing job posts a commit status on each affected PR head, since an issues-triggered job belongs to no PR's check suite.
    • pr_template.yml. Separate because edited must re-run it and would otherwise re-run every scaffold check on a body edit. It reads the body live from the API, since a re-run replays the original event payload.
    • release.yml. The version input is free text and is validated before git tag, the irreversible step, so a bad value is a no-op instead of a pushed tag with no artifacts. release_snap.yml fails before its 30-minute build when the credential is absent, because an exit 0 there let v0.16.67 to v0.16.70 report green while nothing reached the store (#669). Every package job stamps the release version into the fallback literal of blueprintx --version, since packaged installs have no .git.
    • verify_branch_protection.yml (#307). Guards the strict setting, which anyone with admin rights can flip with no red check. GITHUB_TOKEN cannot read branch protection (administration is not a grantable scope), so it reuses GH_PAT_REVIEW_TRIGGER. It runs on push to main, weekly and on dispatch, not on pull_request, because it checks a repository setting and is not a required check. It fails, never skips, without the PAT.
    • docs.yml. Checks out full history so cz changelog sees the tags, and regenerates CHANGELOG.md fresh on every docs build; it is never committed back.
    • secret_scan.yml. Scans full history. A pinned version fixes what is asked for, never what arrives, so the download is SHA-256 verified before extraction, as lint-actions does for actionlint. A graceful skip is right on a contributor's machine and a placebo in CI, so GITLEAKS_REQUIRED=1 turns a missing install into a failure.

    scaffold_checks.yml — notes per job¶

    • No setup step for the stdlib-only gates (function length, complexity of bin/, comment budget, test copy lists, sed portability, git remote guard, scaffold libs): a missing tool cannot make a gate report its own blindness as OK, so there is no *_REQUIRED flag. The complexity job on templates/python-common needs ruff, because C901 is the metric, and hard-fails when it cannot be resolved.
    • Complexity needs a second invocation (#271), scoped to templates/python-common, whose src/ and tests/ the top-level directory lookup cannot see. Function length is not duplicated: its discovery already walks the whole root (measured by planting a 66-line function there).
    • Sed portability. GNU sed -i takes no argument and BSD requires one, so a bare sed -i aborts a scaffold on macOS. sed_inplace() in bin/lib/common.sh is the replacement.
    • Test copy lists. A shared test no scaffold copies is committed and never run in any generated project. Its first run found test_startup_fragility_order.py absent from all five tiers.
    • actionlint. yamllint asks whether the YAML is valid, actionlint whether GitHub will run it, and a workflow GitHub refuses produces no red check. The template workflows are in scope because they never execute here. Its tarball is SHA-256 checked for the reason above.
    • GitGuardian is not a required check (#155). Its population is unmeasured. GitHub gives a Dependabot-triggered run a separate secret store holding none, so the key resolves to an empty string and ggshield exits 3 (#457, PR #400). The job is skipped on the PR author (github.event.pull_request.user.login, never github.actor) when that author is Dependabot. This is not a silent pass: gitleaks scans the same range unconditionally. The fix is gh secret set GITGUARDIAN_API_KEY --app dependabot --repo <owner>/<repo>. The probe is gh api repos/<o>/<r>/dependabot/secrets --jq .total_count, which returned 0, and until that secret exists a Dependabot PR trips the job on every run (the log shows GITGUARDIAN_API_KEY: blank and Error: Invalid GitGuardian API key.).
    • ggshield push range. In ggshield 1.54.0 the previous-commit variable is GITHUB_PUSH_BASE_SHA, which must carry github.event.before; GITHUB_PUSH_BEFORE_SHA and GITHUB_PULL_BASE_SHA appear nowhere in its source, so setting them protects nothing. Without a usable previous commit it scans only GITHUB_SHA~1, one commit of a five-commit push, with exit 0. A branch-creating push (before is forty zeroes) and a manual dispatch run a separate full-repository scan in a separately named step, which is the correct range for a freshly scaffolded project's first push. GITHUB_DEFAULT_BRANCH is deliberately left unset, so do not re-add it as protection: with a real previous commit its fallback is unreachable, and on a branch-creating push its fallback is a bare ref (main..<sha>, no origin/ prefix, because the remote prefix is applied only on the pull_request path). A detached checkout has no local main, so that resolves to nothing and lands back on GITHUB_SHA~1. Prefixing it with origin/ does not help either: on the push that creates the branch origin/main already equals HEAD, so the range is empty. The pull_request path needs no variable, because ggshield reads GITHUB_BASE_REF, which Actions already sets.
    • Scaffold matrix. dry-run-smoke and scaffold-lint-test are CI-only (#384): a skeleton.meta change would trigger one hook, never all six skeletons. envsubst is installed only when missing, because the unguarded apt-get hung two jobs for 6 hours (#192). MULTI_PIPELINE_OPTIN=true forces the MVC multi-intent prompt to yes. The storage opt-in job answers that prompt through the named-key spec on every tier that offers it (api-service-native-db uses the DDD key map, #668), because the plain scaffold never linted files that ship only on an opt-in (#650).
    • Codespell sync. The vocabulary this repository learns must reach the copy that ships into every scaffold; the two lists drifted in both directions and the stale side was the template.
    • Pairing gate. Makefile and tasks.sh exist only at this repository's root, so the script lives at bin/, not in a template.
    • pymarkdownlnt is pinned. .pymarkdown.json enumerates rules one by one, so a rule a new release adds is enabled by default: 0.9.40 added MD049, MD050 and MD051 and turned 9 open PRs red (2026-09-18). Bump it deliberately and re-measure the rule set (#383).
    • Validate-meta tests (#407). The gate blocks merge and had no tests for a missing key, an empty value or a dead scaffold= path.

    Dependabot (#471, #484)¶

    • Version updates for this repository are monthly, not weekly: the three ecosystems (docs venv, ts-common's toolchain, Actions runners) ship no runtime product code, grouping already caps noise at one PR per ecosystem per interval, and security updates run independently on their own toggle.
    • increase-if-necessary, not lockfile-only: both manifests use caret ranges, so every major bump needs a manifest edit, and under lockfile-only no major PR would ever open.
    • Groups are minor and patch only; a group without update-types would bundle majors with routine bumps. There is no labels: key, because bin/pr_gate.py already labels by path and Dependabot comments an error on every PR when a declared label does not exist.
    • The eslint, @eslint/js and typescript majors are held because their peers (typescript-eslint peers on typescript below 6.1.0; the react, import and jsx-a11y plugins cap eslint at 9) exclude them; lift per #720. First match wins, so @eslint/js moves in lockstep with eslint.
    • @types/node majors are held in both TypeScript tiers (#824, closing #798). The types must match the lowest Node a template supports, because newer types let code compile against APIs a Node 22 user lacks: the build passes and the program fails at run time. Both tiers pin ^22, the engines.node floor line. Lift the ignore and raise the pin in the same PR when an engines floor moves to a newer major.
    • Pinning actions by SHA (#369) does not self-update; the Actions ecosystem entry does.

    Generated-project workflows (templates/python-common/.github)¶

    The workflows and dependabot.yml a Python scaffold ships carry no prose. Where a file is the twin of a root workflow, the reasoning above applies unchanged (review_threads.yaml, coderabbit_trigger.yaml, review_retry.yaml, pr-reconcile.yaml, secret_scan.yaml). This section records what is specific to the generated copies.

    tests.yaml¶

    • No outputs: on workflow_call. It once declared ready_for_release as ${{ jobs.test.result == 'success' }}. Only jobs.<id>.outputs.<name> is in scope there, so the output was an empty string on every run while looking like a release gate. It had no consumers; a caller reads the verdict from needs.<job>.result.
    • The job name carries every matrix axis. With only os in it, the 3x5 matrix produced 15 check runs sharing 3 names. A required check is resolved by name, so a green and a red leg of one name are indistinguishable to the merge gate.
    • fetch-depth: 0. The work-ledger gate resolves merge-base(HEAD, default), which a shallow clone cannot find; the gate-integrity gate diffs against main for the same reason.
    • The lockfile check is an unconditional step before the pyproject rewrite. Nested under the install's if: cache-hit != 'true' it never ran on a warm cache, which is exactly the condition that makes it cheap. A stale poetry.lock fails loud: regenerating would re-resolve every dependency to the newest in-range version, a non-reproducible build. A version bump does not invalidate the lock, so poe bump_version never trips it.
    • The cache holds .venv only, keyed on poetry.lock and pyproject.toml. Caching the tracked lockfile lets a restored cache overwrite the committed one. Hashing pyproject.toml alone makes the lock-only diff Dependabot's lockfile-only produces a cache hit, so every bump PR would skip the install and test the pre-bump set.
    • Every gate is an explicit step as well as a pre-commit hook. CI does not run pre-commit, so a gate listed only there is bypassed by a contributor who skips hooks; check-sql-guards shipped one-legged that way and a WHERE-less DELETE reached main (#355). Per-gate points:
      • lint-deps runs inside the Poetry venv and cannot become pipx run deptry: deptry maps a module to its distribution through the environment it runs in, and outside it the verdict inverts rather than degrades.
      • check-comment-language runs in audit mode (no filenames), sweeping every commented file type, because a partial sweep leaves a precedent the next author copies.
      • function-length, fixture-scope, check-complexity and identifier-masking fail when discovery matches zero files. check-complexity hard-fails when ruff cannot be resolved.
      • gate-integrity is diff-scoped (#309): a PR may not weaken a hook, rule, exclude or check without a gate-change-ok: <reason> marker.
      • coverage-floor exits 0 with a message on a tier with no src/capabilities/ (MVC) and migration-graph self-skips on a tier with no migrations/versions/.
      • fixture-scope is a proxy, not a detector (#442); see the gate's module docstring.
      • The others pin one invariant each: check-typing (every src/ class or function carries the runtime checker, Pydantic models excepted), check-provenance (a module that calls read_table also calls stamp_provenance), check-all-exports (a declared __all__ names every public member, which an introspective test that discovers the family through __all__ cannot catch), check-dtypes (no ingested column typed as a binary float, which stores 1984223115.42 as 1984223115.4200000762939453125), check-layer-imports (a third-party dependency is reached through a utils/ seam, in any scope), check-orm-model-guards (#361: bitwise operators in .where(), two create_all, and a duplicate constraint name= across a mixin MRO, each a silent wrong answer at declaration time), specs-structure (a tree with no .specs/ passes, a malformed one fails by name), check-docs-sections, check-docs-code-refs (#159) and check-backlog-ledger.
    • Pinning pins what is asked for, never what arrives. gitleaks and actionlint are unpacked and executed on the runner, so each download is SHA-256 verified before extraction. LINT_ACTIONS_REQUIRED=1 turns actionlint's graceful skip into a failure: the skip is right on a contributor's machine and a placebo in CI.
    • ruff format is a CI step so unformatted code fails, not only lint findings. mypy runs from src/, the single package base, to avoid the "found twice" error on the deeper DDD tree. shellcheck and shfmt are installed so the shell gate runs instead of skipping.
    • || [ $? -eq 5 ] on the integration run. Pytest exit 5 means no tests collected, which a fresh project's empty suite must not turn into a red CI; exit 1 still fails.
    • The coverage floor runs on every PR. The badge step runs only on main and tags, so without the floor step a PR could drop coverage uncaught. The badge uses --local because the default form fetches from img.shields.io, and no CI or release path may depend on a non-essential external host.

    Other generated workflows¶

    • pr-gate.yaml. It triggers on pull_request only, never workflow_run, which fires only from the default branch's copy and so cannot run on the PR that introduces the gate. The gate polls the checks in-run instead. labeled and unlabeled are included so do-not-merge takes effect at once. A pull_request-driven gate never re-evaluates an already-open PR after a policy change; run the workflow_dispatch with backfill: true (or @dependabot rebase) to re-decide every open PR. A new push cancels the previous polling run so two gates do not race on one sticky comment. Event data reaches the script through env: only.
    • release.yaml. A service is deployed, not published, so there is no PyPI step. The version input is free text and is validated before git tag, the irreversible half. The versioned-docs job runs only after the tag is cut, so the site never advertises a version that failed to ship. mike deploys X.Y under the latest alias; a prerelease suffix is skipped in-step so it never moves latest. The dropdown granularity is X.Y, so 1.4.2 and 1.4.7 share an entry. CHANGELOG.md is regenerated by cz for that build and not committed back to protected main. GitHub Pages must serve from gh-pages (poe enable_pages).
    • contract_drift.yaml. A weekly, non-gating reporter on schedule and manual dispatch, never pull_request or push, so it cannot gate a PR or a release. It opens or updates one deduplicated issue and never fails the run; it is inert until a source is added to src/config/contract_oracles.yaml. Dedupe is on the contract-drift label and a hidden body marker, since the label alone can be removed by hand and a job that files an issue per run gets switched off. The report goes in as --body-file so source-derived text cannot inject into a shell command.
    • review_threads.yaml. actions: write is for the stale-run cleanup only. Set REVIEW_THREADS_REQUIRE_RESOLVED to 0 for a reply-only contract; the shipped value is 1. bin/enable_repo_rules.sh seeds REQUIRED_CHECKS with this job's name:.
    • coderabbit_trigger.yaml. The scaffolder sets GH_PAT_REVIEW_TRIGGER when it is exported at scaffold time and prints the command otherwise. Scope the PAT to all repositories if you scaffold often, since a per-repository PAT is edited for every new project. It ships with the review-thread gate: without the gate this workflow is a nicety, without the workflow the gate blocks every PR.
    • secret_scan.yaml. It is opt-in (#287): copied only when GITGUARDIAN_API_KEY is set at scaffold time, the same presence check that propagates the key to the new repo's secrets. It is not in REQUIRED_CHECKS, since a required check that never reports blocks every PR. An absent key fails loud, never skips: ggshield exits 3, distinct from a clean exit 0.
    • review_retry.yaml. GitHub disables a scheduled workflow after 60 days of repository inactivity without announcing it. If rate-limited PRs stop being re-asked, check that the workflow is still enabled before looking for a bug in the script.
    • pr-reconcile.yaml. Cards in a Projects "closed to Done" automation key on the issue closing, so a missed close leaves them in "In review" while the code has shipped, and the problem grows with auto-merge adoption. The workflow calls bin/pr_reconcile.sh, the one implementation shared with the root workflow. On the event path it reconciles that PR; on schedule and dispatch it sweeps a window.

    dependabot.yml¶

    • Ordinary version updates only. Security updates are a repository toggle (poe enable_security), not config.
    • versioning-strategy: lockfile-only. CI installs from the committed lock and refuses to re-lock, so it tests the frozen versions while consumers get whatever the loose >= ranges allow. This refreshes the lock but never rewrites pyproject ranges: narrowing a library's range on a consumer's behalf is not the project's call, and pyproject and lock stay in sync.
    • Solo-maintainer tuning. Minor and patch are grouped into one PR; majors arrive alone and get scrutiny. Each PR (one grouped minor-and-patch update, or one major) is isolated, so a bad bump reddens that PR and never main. A linter bump (ruff, mypy) can ask for a reformat, which is the system working.
    • No labels: key, because bin/pr_gate.py already labels by changed path and Dependabot comments an error on every PR it opens when a declared label does not exist. When a scaffold ships both a bot config and a labelling gate, only one may own labels.
    • Major-line pins go for dependencies whose major is a support decision. pandas is tested on both 2.x and 3.x, so its major bump is a project decision. Add one per such dependency and remove it when the project stops straddling.
    • The Actions ecosystem entry keeps CI off deprecated runtimes, for example a Node version GitHub is sunsetting.

    Review-thread gate tests (templates/python-common/tests/unit/test_review_threads_gate.py)¶

    The test module carries no comments. The points below recur through it; each exists because a simpler form was measured to be wrong. The shapes forced by the complexity-1 ceiling (module data in place of branches, split rather than combined assertions) are the ones recorded for the rest of the suite.

    • Split the loader and the spec. A conjunction in one assertion reports only that the whole thing was false; an absent loader and an absent spec are different faults.
    • Two roster shapes are not interchangeable. _ROSTER is the raw member list; the normalised mapping (login without [bot] to its posts: class, as load_roster returns it) is what the notice helpers take. The thread half of the gate takes every member, the missing-review half only those that can review. Passing the raw roster to a helper that expects the normalised one matches nothing and returns "": a green-looking empty answer, not an error.
    • A review is pinned to a commit (#220). The fixtures use two distinct oids, the PR head and a commit it superseded, because the gate's question is "which commit was this review written against?"; measured on #219, where the only review was attributed to a commit pushed five minutes before the head. A completion notice is evidence only when it postdates the head commit's committedDate, otherwise it describes code the branch has since moved past (raised by review on #339).
    • The pagination case is the "expensive shared setup" one from tests/CLAUDE.md (#544): one two-page fetch backs five independent claims, so it runs once in a module-scoped fixture. The two pages are data in a side_effect sequence, not a stub that branches on its cursor arguments (a branch put a decision in the test and the green never said which side ran), and Mock records the calls for free.
    • The bot-login spelling is why the gate was silently vacuous: REST spells the login with a [bot] suffix, GraphQL without, and before the fix the GraphQL spelling counted as an answer. The human login is the load-bearing third case: it passes through untouched, so nobody is normalised into looking like a reviewer.
    • The REVIEW_THREADS_REQUIRE_RESOLVED flag has three claims, one test each (#544): three different verdicts, not one assertion over three inputs; collapsing them hid the third. CI no longer passes False (#196): delegating the resolve half to required_conversation_resolution looked safe, but that setting drops an outdated thread (#193: merge enabled over an unresolved outdated thread with 29 of 29 checks green). The flag survives for callers that cannot re-evaluate a resolve, so the reply-only mode must keep working and must not quietly disable the job altogether.
    • A redundant re-review is not an unreviewed PR (#259). The reviewer's boilerplate is copied verbatim from #264's own comment stream; it is appended to every outcome (performed, rate-limited and failed alike), which is what defeated the first draft of the check.
    • Real notice bodies, never retyped (#364, #433). The chat-quota notice (PR #363, 2026-08-30T18:44:28Z), the review-quota notice (PR #317, 2026-08-29T17:11:51Z) and the file-cap notice (PR #424, 2026-09-11) are fetched with gh api graphql; the issue the first closed was itself written against retyped text that classified differently from the real bytes. A second, unrelated "Review skipped" reason (measured on PR #400, a one-file bot-authored PR, clearable simply by asking, unlike the structural cap) shares the bare prefix with the file-cap notice, which is what makes it a genuine negative control. The bot suffix is stripped first, or the notice lookup silently finds nothing.
    • Classification by declared structure (#630, docs/faq.md). Each shape is a trimmed copy of a real body from this repo's PRs (#347, #671 to #687), and the witness is the same text with only its structural marker removed. The real CodeRabbit body from #347 has its only finding in a body section, not an inline thread.
    • The display budget must not reach a matcher (#372). summarise_reviewer_notice cuts a notice to 200 characters so a failure message stays readable. Two matchers used to read that cut string, so a phrase past the budget read as absent. Over 112 real reviewer notices, 4 flipped UNKNOWN to OK (phrase at offsets 394, 583, 583 and 2700) and 4 lost a completion phrase; both directions are silent.
    • A review carries forward across a merge of the base (#698). The patch-id output is <patch-id> <commit-id>, and unpacking fails loudly on empty output instead of an IndexError. The merge of main into the branch conflicts by design.
