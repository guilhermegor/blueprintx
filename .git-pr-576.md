## Description

Ships the `docs/` boundary guard to generated Python projects (owner decision 2026-10-14 on #576): their `docs/` is published documentation only; trackers, specs and backlog live in `.specs/`.

## Changes Made

- `bin/ci/check_docs_boundary.sh` now accepts `--root <dir>` and resolves its root from either `bin/ci/` or `bin/` (same pattern as `check_specs_structure.sh`). One implementation; tab-indented so the scaffold's shfmt hook accepts the copy.
- Copied to `bin/check_docs_boundary.sh` by `scaffold_python_templates.sh` and `python_lib_minimal.sh` (one line each).
- Wired into `templates/python-common/.pre-commit-config.yaml` (`docs-boundary`) and `tests.yaml` (Run Docs Boundary Gate).
- Should-fail tests: `tests/test_check_docs_boundary.sh` (generated-project layout, `docs/backlog/x.md` fails, bad `--root` fails) and `scaffold_lint_test.sh` (real scaffold passes, planted `docs/backlog/x.md` fails).
- `CONTRIBUTING.md`/script header: the "scoped to BlueprintX" decision is replaced by the new one.
- Comment-budget baseline lowered.

Confirmation on `origin/main` before writing: no `templates/*` tier ships `docs/backlog/` or other deny-listed material under `docs/` (#690 moved the ledger to `.specs/backlog/`); the gate previously had no `--root`.
