# Duskko — o que falta na BlueprintX antes de scaffoldar

**Criado:** 2026-08-16 11:00 · **Estado da base:** `v0.15.3` publicada (PR #170 mergeado)

Este arquivo existe para uma pergunta só: **o que ainda impede o `make new` do duskko?**
Resposta curta: **nada.** O que segue é a fila do que melhora o duskko depois, ordenada por
quanto custa deixar para depois.

O duskko é um `mvc-service-native-db`: coleta na **API da Tesouraria** (substituindo as queries
de `contexto_duskko/config/consultas_sql/`), tratamento, persistência em **SQLite**. Ambientes:
Windows + proxy TLS da XP **e** Linux/WSL.

## Quando scaffoldar

**Pode ser agora.** A base está publicada e verificada: 226 testes passando nas duas tiers MVC
via scaffold real, lint limpo, árvore estável. As filas 1 e 2 são melhorias, não pré-requisitos.

O único custo real de scaffoldar antes delas é o backfill manual — e para o duskko ele é barato,
porque o projeto ainda não existe: recopiar um arquivo de `templates/` é trivial enquanto ninguém
o editou.

Comando: `make new` → python → `mvc-service-native-db` → nome `duskko`.
