# Offline git workflow — merge/checkpoint/diff-export recipes (#142)

Tracks issue #142: backport the offline git workflow's remaining gaps into
`templates/common/`. Most of the scope (`new_branch.sh`, `git_merge_to_main.sh`,
`git_diff_{export,check,apply}.sh`, `commit.sh`, `ship.sh`, `protect_branch.sh`,
`ensure_dir()`) already existed in `templates/common/bin/` before this PR — this
work closed the remaining measured gaps.

## Scope of this PR (`templates/common/**`, `docs/`)

- [x] `ensure_dir()` UNC-safe helper already existed in `templates/common/bin/lib/common.sh` —
      but 3 call sites still used bare `mkdir -p`. Swapped:
      `bin/ship.sh` (3 call sites), `bin/export_repo_content.sh`, `bin/git_diff_export.sh`.
- [x] `record_checkpoint()` in `bin/git_merge_to_main.sh` — the missing "converge on the
      checkpoint variant" decision from the issue. Before every merge it now: seeds
      `docs/checkpoints.md` with a header (first run only), appends an entry (timestamp,
      source tip, target-before hash, literal `git reset --hard <hash>` undo line), and
      commits it on the source branch — a normal, fully-gated commit (whatever pre-commit
      hooks the project has installed run on it), so it can take several minutes. Verified
      both directions: succeeds and produces the correct checkpoint entry; a rejecting
      pre-commit hook correctly aborts before the merge and leaves the tree exactly where a
      human can retry.
- [x] `mkdocs.yml`'s `checkpoints.md` exclusion already existed in every skeleton
      (ddd-service-native-db/orm-db, mvc-service-native-db/orm-db, lib-minimal) — left
      untouched per the issue's "keep the existing exclusion" instruction.
