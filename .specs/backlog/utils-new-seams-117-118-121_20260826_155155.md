  (`utils/email/email/…`). Fixed in `python_mvc_service.sh` / `python_mvc_service_orm.sh`:
  `mkdir -p` + `cp -r optional/email/. dst/` (merge, not nest).

  warns about): all 4 service scaffolds hand-maintain a flat `utils=(...)` array; the

  `python_mvc_service.sh`, `python_mvc_service_orm.sh`): replaced with `ms_office`, added
  `xml_reader` and `email`. The per-util test-copy step assumed one `test_${util}.py` per
  entry; `ms_office`/`email` each ship multiple test files, so — after a first attempt using a
  `test_${util}*.py` glob broke `bin/ci/check_test_copy_lists.py`'s static regex, which requires
  the literal `test_${util}.py` form — the generic loop was kept exact-match and five explicit
  `cp` lines were added after it in all four scaffolds, one per `ms_office`/`email` test file.
  The Excel test was renamed to `test_ms_office_excel_sheet_names.py` to match its explicit

  added `xml_reader.py` there too (deptry caught the unused `defusedxml` dependency
  immediately), and updated `check_test_copy_lists.py`'s `DICT_EXPECTED_ABSENT` for the renamed

- **Cross-module `FileContract` identity mismatch in tests**: `xml_reader.py` imports

## Review round (PR #285)

Four CodeRabbit threads, all independently verified before acting (never applied blind):

- **`xml_reader.py` — two real path-resolution bugs.** (1) A `*` wildcard tried only the
  FIRST matching child; a row whose first child does not itself complete the rest of the path
  (e.g. a `Meta` block with no `FinInstrm` under it, sitting before the `New` block that has
  one) resolved to `None` even though a later sibling would have matched. Fixed by replacing
  the linear walk (`_walk_to_last`) with a backtracking one (`_resolve_segments` /
  `_segments_exist`) that tries every matching child at each intermediate segment. (2) `@name`
  attribute lookup used `Element.get(name)`, an EXACT key match — Clark notation for a
  namespace-prefixed attribute (`{uri}name`), so a source writing e.g. `xsi:Ccy` was silently
  missed even though the module's own docstring promises namespace-agnostic matching. Fixed
  with `_get_attribute`, matching by local name like element segments already do. Both proven
  with new fixtures (a `Meta`-before-`New` document; a document declaring an `xsi:` prefix on
  the attribute), not just read.
- **`html_body.py` — real, high-severity: unescaped plain text reaches an HTML body.** Proven
  before fixing: `to_html_body("report <final>.xlsx & <script>alert(1)</script>")` returned
  the payload byte-for-byte, including the live `<script>` tag — this seam ships to every
  generated project and any backend that sends the result as HTML would render it. Fixed with
  `html.escape()` on the plain-text branch only (the already-HTML early return is untouched on
  purpose — that path is a caller composing real markup deliberately).
- **`excel_sheet_names.py` — the cell-reference rule was WRONG, not merely opinionated.**
  Verified independently against Microsoft's own worksheet-rename documentation (fetched
  directly, not taken from the reviewer's citation) plus a second search on the "cannot look
  like a cell reference" rule: that rule is real, but it governs *defined names* (the Name
  Manager), a different namespace with different rules — a worksheet literally named `Q1` is a
  valid Excel sheet name, referenced as `Q1!A1`. The rule was removed rather than kept on the
  strength of "the reviewer said so" or discarded on "seems annoying" — both checked, one held.
- **This file — the copy-list description was stale** by the time of review (the mechanism had
  already changed again, from a glob back to explicit `cp` lines, to satisfy
  `check_test_copy_lists.py`). Corrected above.
